# 7.9b Agent — the lane and the assistant

The tools, their parity check, the dev tools and the transport are §7.9a.

**The lane** (road map 12 A1; §11 AI-2, AI-3, AI-5, AI-7, AI-12). Every tool
call goes through `AgentLane` (`AgentLane.swift`): the MCP trampoline's
`serve`, on the server thread, and the assistant session's `submit`, which
returns at once and answers on its document's serial queue (one per document
with a call outstanding, so a question pending in one window holds no other
window's calls, #148). One `NSLock` admits
one call at a time from either caller, which is what keeps `callScope` and
`callDocument` race-free; it is never taken on main. The lane runs an
`offMainTools` member in place and every other tool on main.
`AgentServer.prepareCatalog()` builds the catalog, fills the argument gate
and runs the parity check once per launch, from `main.swift` before
`NSApplicationMain`, so the gate is full whether or not the server is ever
started; `start()` takes its memoised string. A `submit` is pinned to its
window's document (`callDocument`, which `targetDocument` checks first): no
`project` argument means that document, and a `project` naming another is
refused by name. `AssistantToolTable.swift` is AI-7's one table: the dev
tools, `record_screen`, `close_project` and `transcribe` with
`engine: "assemblyai"` are withheld and refused by the lane; `export`, `export_captions`, `save_project`
and `consolidate_media` are put to the session's ask-first hook BEFORE the
lock, naming where they write and saying REPLACES when a file is already
there, and a Deny answers "The person declined: …" without running the tool.
An MCP caller is never asked and never refused by the table. **A call that
arrives while any open document is mid-gesture waits for mouse-up, then
runs** (AI-12, #144): every main hop, `onMain` included, is
`AgentLane.onMainWhenIdle`, which retries every 20 ms while a timeline,
canvas or inspector-slider gesture is live, so the call lands as its own undo
step above the gesture's; called on main it runs in place.

**The helper** (road map 12 A1 part 2 and A4; §11 AI-1, AI-2). `agent/` is
Bun-compiled (`bun build --compile --target=bun-darwin-arm64`) from `src/`,
which is meant to be one diff with Rasterize's own `agent/src/` (#147). The
helper owns no tools; it speaks JSON lines on stdio. In: `configure` with the
key, the model, the system prompt, the catalog, `core_tools`,
`search_guide`, `compaction_instructions`, the chat settings and, when set,
`api_base`; then `send`, `cancel`, `reset`, `settings` and `tool_result`. Out: `ready`,
the deltas, `tool_request`, the compaction events and `turn_finished`.
`project.yml`'s last post-build step, "Build Agent Helper", runs
`agent/build.sh helper`, which copies the helper to
`Contents/Helpers/framejob-agent` and signs it `--options runtime` with
`agent/entitlements.plist` — exactly `com.apple.security.cs.allow-jit`,
without which the helper dies at launch under the hardened runtime (A0's H6)
— before Xcode signs the app. No bun fails the build; nothing skips it. The
same helper ships in Release and Distribution, and `make dist`'s
`dist_check.py` holds each bundle's to that contract (D6–D13: present,
`runtime` in its flags, entitlements exactly `allow-jit`, no dev-tools
marker).

**The assistant session** (road map 12 A1; §11 AI-1, AI-4, AI-5, AI-7, AI-8,
AI-11, AI-13). Each editor window has at most one `AssistantSession`
(`AssistantSession.swift`, a port of Rasterize's `AssistantHelperSession`),
held by the window's controller and closed with the window. Opening one
checks, in order and each refusing in its own sentence: the base-URL override
`RC_ASSISTANT_BASE_URL` (AI-13; plain `http` only for a loopback host), the
person's key (`SecretStore`'s `anthropic-key`, then `ANTHROPIC_API_KEY`;
with the override set and no `-RCSecretFolder` no key file is opened), the
catalog prepared at launch (read, never prepared: AI-3), and the bundled
helper `Contents/Helpers/framejob-agent`. The helper runs with exactly
`HOME`, `TMPDIR` and `PATH=/usr/bin:/bin`; its first stdin line is
`configure` with the key, the model (`FrameJobAssistantModel`, else
`claude-opus-5-5`, AI-11), the system prompt, the assistant's catalog
(`AssistantToolTable.assistantCatalog`), the core tools
(`get_project`, `render_frame`, `undo`, `redo`, loaded up front; every other
tool is found by tool search), the search guide, the compaction
instructions, the chat settings and, when set, `api_base`, `price_cache` and
`price_feed` (road map 13 P2, §11 P-5). The key is in
that line and nowhere else. **Prices** (§11 P-1, P-2, P-5): the helper prices
from its bundled `agent/prices/anthropic.json` unless `price_cache` names
its cache, `anthropic-prices.json` in the spend folder
(`~/Library/Application Support/Frame Job/`, or `-RCSpendFolder`; none with
`RC_ASSISTANT_BASE_URL` set and no `-RCSpendFolder`, and with the override
the cache is passed only beside `-RCPriceFeed`). A cache that is absent,
invalid, or 24 h old refreshes from LiteLLM's raw `main` file (or
`-RCPriceFeed`, https or loopback http only) and is written on success; a
failure keeps what was in force and says why. The helper emits `prices`
(`{kind: bundled|cached|fetched, as_of, problem?}`) once per `configure` —
before `ready`, or when the refresh settles — and a `cost` event for every
response and every compaction summary (`model`, `usage`, `cost` from
`price()`, `prices`), at the prices in force when the turn started; a
response cut short by Stop or an error is priced once, from the usage its
stream had reported, as a `cost` with `partial: true` before any `error`
(§11 P-8; a request that failed before `message_start` has none). The app
appends one `.sortedKeys` line per `cost` to the spend folder's
`spend.jsonl` (0600; `time`, `service`, `model`, whitelisted `usage`,
`dollars`, `unknown`, `rows`, `prices`, and `partial: true` for a response
cut short; never a key or content), and the
transcript ends each turn with `Cost: … · Frame Job's estimate at LiteLLM
prices (…)`, "unknown" when a response could not be priced, never $0, and
`at least … (a response was cut short)` when one was cut short
(`AssistantSpend.swift`). Two figures sum those dollars and add no pricing
of their own (road map 13 P4, §11 P-4, P-7): the Assistant tab's Spend row,
the transcript's sum of `cost` events since its last Clear or ended
conversation (in memory, so it needs no spend folder), and Settings ▸
Assistant's month line, a fold of `spend.jsonl` over the UTC calendar month
(`AssistantSpendMonth.swift`, folded off main on its one serial queue, read
when Settings shows and after each line recorded while it is visible),
which counts unpriced and unreadable lines rather than adding them as $0 and
says "This launch keeps no spend ledger." with no spend folder. Both say
they are Frame Job's own estimate. The dev tools' `events` show a `cost` only as
`{type, cost: {kind, dollars|cause}, prices}`, with `partial: true` for one
cut short (`AssistantSpend.toolView`), never its model or usage. Every tool the helper asks for goes through
`AgentLane.submit`, pinned to the window's project, ONE at a time in the
order asked; each result is spliced verbatim into a `tool_result` line, and
every write goes through one serial queue. An ask-first call is a pending
question the person answers Allow or Deny; Stop, closing the window, the
helper's death and the session's release each answer it as declined, so
every question the lane asks is answered exactly once. Stop also answers
every call not yet run "Cancelled by the user.", and cancels the running
call's token (§11 AI-16): a running `export` or on-device `transcribe` stops
and answers its own sentence ("The export was cancelled.", "The
transcription was cancelled."); any other running call finishes. A dead helper closes the session, and the next send opens a new
one.

**The prompt** (road map 12 A3; §11 AI-7, AI-9, AI-15). The system prompt,
the tool-search guide and the compaction instructions are Swift literals in
`AssistantPrompt.swift`, fixed for the session: they interpolate the
timescale (`ReelTime.perSecond`), the ask-first and conditional withheld rows
of `AssistantToolTable.rows`, the shared id kinds and the context tag, and
the guide renders `searchTopics`' words, which cover every tool of the
assistant's catalog but the core tools exactly once. What changes between
turns rides on each person message instead (AI-15): `send` writes the text
behind a `<framejob_context>` block (`AssistantLiveContext.swift`) of the
project's name and path, the open nest, the playhead in ticks and seconds,
and the selection, each label a key of `get_project`'s answer. `make test`
runs `tools/proof/assistant_prompt_proof.py --probe`, whose rows F1–F8 check
the texts against the code — every backticked token a tool or a path of
argument names and `get_project` keys, no withheld tool named, the
timescale, the id kinds against a fixture, the topics against the catalog,
the ask-first rows, no blank line and the length bounds, the context block
exactly with every `none`/`null` literal in double quotes and the no-scope
word the block's own, and each ask-first row's reason a write, as "These
tools write files" claims (#158) — and M1–M6 make each checker fail on a
mutated copy.

**The Assistant tab** (road map 12 A2; §4.3, §11 AI-4, AI-8, AI-11, AI-14) is
the person's door to that session: the inspector's fourth tab, and View ▸
Assistant ⌃⌘A to show it. The composer's Send is `assistantSend` on the
window's controller, which opens the session (an open failure is an error
line in the transcript) and sends while idle; the transcript is the
session's `onEvent` stream mapped to entries (`AssistantTranscript`), kept on
the controller; Allow, Deny, Stop and Clear are `answer`, `cancel` and
`close`. Settings' Assistant pane holds the key, the model and the chat
settings (compaction's threshold or off, and whether old tool results are
cleared), and under them the month's spend (above); a Save,
Remove or a model that actually changes ends each window's conversation,
since a session keeps what it was opened with, while a chat-settings change
is written to each open session as `settings` and ends nothing. **None of it
has an MCP mirror, deliberately:** showing the tab is view state, which the
dev tool `select_inspector_tab {tab: "assistant"}` covers in a Release build;
the key, the model and the chat settings are the person's settings, which no
tool reads or writes (AI-8, AI-11, AI-20); and the conversation itself is the assistant's, whose calls
already ARE tool calls through the lane. `assistant_send` / `assistant_answer`
with `pane` drive the tab's own controls for a proof.
