# 7.2 Composition plan

Rebuilt by Swift only when the plan JSON differs from the current one
(a string compare; the plan is cheap to compute, so Swift asks for it after
every edit and compares).

```json
{
  "timescale": 600000, "duration": 36000000, "fps": [30, 1],
  "render_size": [1920, 1080],
  "video_tracks": [
    { "id": 1, "segments": [
        { "clip": 17, "media": 1, "source_in": 3000000, "source_duration": 12000000,
          "start": 0, "duration": 12000000 } ] },
    { "id": 2, "segments": [ … ] }
  ],
  "audio_tracks": [
    { "id": 1001, "track": 3, "segments": [
        { "clip": 17, "media": 1, "source_in": 3000000, "source_duration": 12000000,
          "start": 0, "duration": 12000000, "pitch": "spectral" } ],
      "ramps": [ { "start": 0, "duration": 600000, "from": 0.0, "to": 1.0 },
                 { "start": 600000, "duration": 10800000, "from": 1.0, "to": 1.0 },
                 { "start": 11400000, "duration": 600000, "from": 1.0, "to": 0.0 } ] }
  ],
  "instructions": [
    { "start": 0, "duration": 12000000, "required_track_ids": [1, 2] },
    { "start": 12000000, "duration": 3000000, "required_track_ids": [] }
  ]
}
```

- **`output`** (format 23, §11 HD-2, HD-13): `"hlg"` after `render_size`
  in an HLG project's plan and absent otherwise, so every SDR plan is the
  text it was. Every composition of a plan with it is converting
  (`ConvertingCompositor`) and BT.2020/HLG (`CompositionBuilder`, §7.5), and
  switching the output changes the plan, so `Playback.update` rebuilds.
- **A video segment's `input`** (format 19, §11 GR-16): present ONLY when
  the segment's media has a Camera Log — `{"log": "slog3", "gamut":
  "s_gamut3_cine"}` or `{"lut": 12}`, the recipe layer's `input` (§7.3) — so
  every other plan is byte-identical to the one before it. A plan with one
  makes its composition a converting one (`CompositionPlan.convertsMedia`,
  `CompositionBuilder`, §7.5), and setting, changing or clearing a media's
  Camera Log changes the plan, so `Playback.update` rebuilds. A PQ file's
  effective peak (format 22, §11 HD-12) joins it as `peak` — `{"peak":
  4000}` alone, or beside `log`/`gamut` or `lut` — whenever the media has a
  reading or an override; a PQ file whose import read nothing publishes no
  `input`, so its plan is the text it was.
- **An audio track's `track`** (§11 AU-107): the id of the timeline track
  whose walk placed it — a nest's contents carry the nest clip's track —
  written after `id` on every audio track (the plan is not persisted, so no
  format bump). Swift keeps the map composition track → timeline track per
  build (`BuiltComposition.audioOwners`), each format family included, and
  an audio export's stems read their tracks' composition tracks through it
  (§7.8, AU-108).
- **An audio segment's `track_pans`** (format 35, §11 AU-104): the pans of
  the tracks its clip plays through, innermost first — its own track, then
  each enclosing nest clip's — clamped to ±1, those inside a nest clip whose
  base `audio.mono` is true dropped at that stage (the fold flattens them),
  zeros dropped, and the key absent when none remain, so every plan without
  a track pan is the text it was. The tap applies the product of their
  `AudioPanLaw` pairs to channels 0 and 1 after the clip's own pan and an
  enclosing nest's fold and before the clip limiter; a segment with
  `track_pans` gets a tap even when no clip asks for DSP. A track's VOLUME
  is not here: it is a factor of the envelope (`ramps`), after the mute, at
  every stage (AU-103).
- **An audio segment's `automation`** (§11 AU-85): `[{"at": <ticks>,
  "audio": {…}}, …]`, after `track_pans`, only when the segment's
  innermost clip has an action whose end's `audio` names a tap key (`mono`,
  `pan`, `compressor`, `noise_reduction`, `limiter`, `isolation`, `eq`,
  `hum`, `channels`, `gate`, `de_esser`, `leveller` — the twelfth, §11
  AU-66), so every other plan is the text it
  was. The points are at the voice's start and end, each such action's
  start and end and, inside an eased one, the envelope's 1/30 s grid, in
  project ticks, sorted; each `audio` is the clip's evaluated audio there cut
  to the tap keys (`isolation` present at 0). The tap reads a run's settings
  at its anchor on an absolute 32-frame grid and joins the points linearly —
  pan per sample, isolation's Amount per frame — and switches at a point's
  frame (AU-87); a stage switched on at any point runs for the whole track,
  and a segment with `automation` gets a tap even when no clip's base asks
  for DSP.
- **A nested audio segment's `path` and `origin`** (§11 TX-10): after
  `automation`, only on a segment whose voice has more than one stage (a
  clip inside a nest): `path` is the enclosing nest clip ids outermost first,
  then the clip's own (two clips showing one nest give two segments with
  distinct paths), and `origin` the project time of the inner clip's first
  frame, which the timeline transcript moves a nested word by (§7.9f). A
  top-level segment carries neither, so every plan without a nest is the text
  it was. `PlanSegment` reads `path` as the clip alone when absent and
  `origin` as nil; nothing that builds a composition reads either.
- **A/B assignment.** Per timeline track, clips in start order; each goes
  to the first composition track (of that timeline track's set) whose last
  segment ends at or before the clip's start; a new one is added when
  none does. With the overlap rule (§6) that is at most two per timeline
  track — except for a nest clip, which stands for a whole stack and needs
  as many as the nest's own tracks do. Composition track ids are stable
  small integers (video 1…, audio **1001…**) and Swift creates tracks with
  `preferredTrackID:` equal to them, so the recipe can name a track by the
  same id. The two ranges are far apart because `MAX_TRACKS` is 64 counted
  across the timeline *and* every nest, so up to 128 video ids can be
  handed out; `CompositionBuilder.makeTrack` throws on a collision rather
  than renumbering. Segments on one composition track never overlap; gaps
  are left empty (AVFoundation treats them as no frame). The whole
  assignment runs over the FLATTENED timeline: a clip inside a nest gets a
  segment at `nest clip start + its own start`, clipped to the nest clip's
  extent, exactly as a timeline clip does. **An audio segment goes only on a
  plan audio track of its own `pitch`** (§11 #190, #211, SY-26, SY-39): a
  track is free for it when its last segment ends in time AND has the same
  pitch NAME — one of three: `off` (keep pitch off, or keep pitch at
  0.999 ≤ speed ≤ 1.001, speed ≠ 1: varispeed), `time_domain` (keep pitch
  at 0.98 ≤ speed ≤ 1.02 outside that, speed ≠ 1) and `spectral` (keep
  pitch anywhere else) — so every plan audio track has ONE `pitch`, Swift's
  first-segment read of the algorithm holds, and each clip's own pitch
  setting is honoured. A
  clip's "own track" for the ducking rule below is its COMPOSITION track,
  so this split can move an abutting neighbour of the other pitch mode out
  from under that exemption: a ducking clip now ducks it by its extent and
  release (accepted, §11 #190). **Above ×12 a clip has no audio segment at
  all**, in either pitch mode (`AUDIO_SPEED_MAX`, published by
  `rc_speed_limits`), because an export's loudness pass never finishes once
  a clip's audio plays much faster; its video segment, the recipe and the
  file are unchanged. **An audio plan track is split by
  source FORMAT in Swift** (§11 R2-1): `CompositionBuilder` puts each
  distinct source audio format of one plan audio track on a composition
  track of its own — the first keeps the plan's id, later ones take ids past
  every plan id and the placeholder's — because the preview's tapped item
  does not play a track that changes format; the plan does not change.
  **A composition audio track none of whose segments has a source** (missing
  media, a pending reverse or ramp render) holds the bundled `Silence.caf`
  back to back over [0, its last segment's end), never scaled, in place of
  its empty edits, which an export cannot read (§11 #336).
- **Speed / freeze.** `duration != source_duration` means Swift inserts
  the source range then `scaleTimeRange` to `duration`. A `still` clip is
  a segment whose `source_duration` is exactly one source frame — the
  freeze-frame idiom; no image extraction needed. **An audio segment's
  insert is moved by its composition track's leads**
  (`CompositionBuilder.placement(of:shift:)`, §11 SY-24, SY-25): a
  time-scaled segment on an `off` track reads its source 575 ticks (46
  samples) earlier, a track whose tap runs noise reduction has its
  media placed 6,400 ticks (512 samples) earlier, and a track whose tap runs
  the clip limiter (any clip on it with `audio.limiter`, §11 AU-23) 1,975
  ticks (158 samples) more, its tap looking its clips' settings up 1,975
  ticks ahead of the buffer's time so each stage after the noise reducer
  meets its own clip. The head of the clip's live chain, after the isolation
  pass below — the channel pick, then the EQ and the hum notch (§11 AU-30,
  AU-34) — runs BEFORE the noise reducer, so on a noise-reduced track the tap looks the head's clip up a
  further 6,400 ticks ahead and cuts a buffer's runs at a clip change of
  either lookup; a lead that would reach
  before the track's 0 or the source's 0 cuts the segment's head to empty
  time instead. **A non-48 kHz source's audio, or an MP3 whose encoder delay
  Core Audio leaves in, is read from a 48 kHz copy** (`AudioRateCopy`, §11
  SY-23, SY-36), because an empty edit before a non-48 kHz segment is
  rate-converted wrongly, and the MP3's copy starts past that delay
  (`MP3Gapless`); video reads the source.
- **A ramped clip** (format 27, §11 SR-10): a media clip one of whose
  actions ends at a `speed` (§5.4). Its VIDEO is one segment per held span
  of its rate and, inside each ramp, one per canvas frame (boundaries at
  the span's edges and every frame start strictly inside it, in project
  time); segment k reads `in + round(S(t_k))` for `round(S(t_k+1)) −
  round(S(t_k))` (at least 1), clamped into the file as a constant segment
  is, so the source is contiguous and totals `round(S(duration))`. All of
  one clip's segments are placed as ONE unit — on the first composition
  track free for its first segment — so the recipe names one track for it.
  Its AUDIO is one segment over the clip's slot, `pitch` `off`, with no
  SY-24 lead, carrying `"ramp": {"keep_pitch", "glide"?, "map"}`: `map`
  the breakpoints `[clip tick, source tick]` (at 0, the duration, every
  span edge and every 600 ticks from each ramp's start, each source above
  the one before), `glide` (only with keep pitch on) the ramp spans in clip
  ticks, abutting ones merged (§11 SR-11) — kept in the plan and in the
  render's cache key, but since SR-13 it shapes nothing: keep pitch on
  renders the whole map in rate mode. Swift renders that audio offline
  (§11 SR-6) into `cache/ramp-audio/`, one file per plan ramp segment, and
  plays the ready render as the segment's source from its start at ×1 —
  `[0, duration)`, never scaled, no lead (§11 SR-12); until a render is ready
  the segment is empty time and its picture plays. It is left
  out above ×12 when the clip's PEAK rate — the greatest rate it names (§11
  SR-19 (d)), read off the clip itself even when a nest clip cuts it short — is
  above `AUDIO_SPEED_MAX`. A nest clip's tail cut truncates both.
  **A constant clip's time-scaled Keep pitch off audio segment** (a `media`
  source, D > 0, `duration != source_duration`; §11 SR-28) carries
  `"ramp": {"keep_pitch": false, "map": [[0, source_in], [duration,
  source_in + source_duration]], "constant": true}` — the segment's own
  lifted range — and is rendered, cached and played exactly as a ramp's,
  at ×1 with no SY-24 lead; its `pitch` stays `off`, its video segment is
  unchanged, and `constant` shapes no file. Every other clip with no speed
  end — Keep pitch on, ×1, a freeze — and every source but `media`, plans
  as before, byte for byte. `rc_project_source_map` (§7.1, §11 SR-20) answers that segment's
  `map` for Swift's readers, unlifted, and a constant clip's two points.
- **Audio envelopes** are per composition audio track, piecewise-linear,
  covering the track's whole extent, with fades, volume, volume actions
  (sampled at 1/30 s across their span), ducking (every other clip's
  envelope multiplied by `level` over the ducking clip's extent with
  linear attack/release ramps — or, a speech duck, format version 29, §11
  AU-112, the minimum of that curve over each of its widened speech spans,
  sampled at each span's four edges and wherever two spans' curves cross —
  a release meeting a later span's attack, or that span's own release —
  for every overlapping pair, not only neighbours, #386) and — format version 7 — the **transition
  crossfade** already folded in, **multiplied by the same
  quantities for every nest clip the segment is inside** — turning a nest
  down turns everything in it down, and muting one silences it. Muted
  clips and muted tracks produce a 0 envelope, and so does a track
  silenced by a solo: while any track in a container's track set — the
  timeline's, or one nest's own — has `solo`, every track in that set
  without it is treated as muted, and mute wins (a track both muted and
  soloed stays silent). The rule is on the set, not on what plays: a
  soloed track holding nothing audible still silences the rest. Audio
  only, and an envelope exactly like mute — the plan's segments,
  `plays_audio` and `assign` never see it, so a solo changes ramps and
  nothing else (which the app rebuilds on, as it does a mute or a
  volume change: the ramps are part of the plan JSON §7.6 compares); a
  solo inside a nest
  is judged among that nest's tracks alone, and a timeline solo on some
  other track silences a whole nest through the nest clip's own stage, by
  the same multiply.
  **The crossfade** (format version 7) is one more factor in that product:
  an overlap whose `transition_in.audio` is true multiplies the outgoing
  clip by `cos(p·π/2)` and the incoming one by `sin(p·π/2)`, over the same
  EASED progress §7.3 hands the compositor. Constant power rather than
  equal gain because the two clips of a transition are uncorrelated
  material, where `cos² + sin² = 1` holds the level and a linear pair dips
  3 dB (§11, R5-2). That is `audio_shape`'s default, `plus_3db`; another
  shape (format version 29, §11 AU-115) multiplies the incoming clip by its
  `gain(p)` and the outgoing by `gain(1 − p)`. A fade in a shape other than
  `linear` (AU-114) is sampled on the same grid across the fade. It is
  sampled across the overlap on the action loop's
  own grid — 1/30 s, widened so one span can never contribute more than
  4096 breakpoints — because neither the sine law nor an eased progress is
  a straight line. Mute, solo, ducking, volume and the fades all keep their
  precedence, since the term multiplies rather than replacing anything, and
  a pair where only one clip has sound still fades that one. **Every STAGE
  multiplies its own term**, which is where the sound parts company with
  the picture: a clip inside an overlap inside a nest that is itself in a
  transition gets BOTH fades, where §7.3's recipe picks the clip's own
  transition and stops. That is right for sound — both fades are audible —
  and it is deliberate rather than an oversight in one of the two.
  **`mono` is not in the plan at all** and never was:
  `AVMutableAudioMixInputParameters` applies gain over time and cannot
  combine channels, so the flag this paragraph used to promise ("a
  per-segment flag Swift applies with `AVMutableAudioMixInputParameters`
  where possible") described something the API cannot do — and nothing
  applied it, from M2 until road map 2's phase 5. It is sample work, so it
  travels the way pan, the compressor and noise reduction do (§4.3): per
  clip, beside the plan, into the processing tap, where it is the head of
  the Mix stage. A project that saved `mono: true` before phase 5 does now
  sound different, which is the feature.
  **Voice isolation is the tap's first pass** (§11 AU-53, AU-54): before the
  chain, a segment whose clip asks for `audio.isolation` a > 0 and whose
  render is READY as the composition is built is crossfaded with it,
  `dry + a·(wet − dry)` (exactly the render at a = 1). The renders are read
  into memory at build (`CompositionBuilder.isolatedAudio`), and each span
  is placed through the segment's own `placement(of:shift:)`, so the
  noise reducer's and the limiter's leads compose:
  `[r(at), r(at + duration))` in 48 kHz composition frames,
  `r(t) = ⌊(2t + 12)/25⌋`, and the wet index is the frame plus
  `r(source_in − at) − window.first` — the difference rounded
  ONCE, so a place and a source-in off the 48 kHz grid (29.97 fps) cannot
  round apart. A render not on disk adds no span and earns no tap, so the
  clip plays dry until the editor rebuilds on its landing; a tap at a rate
  other than 48 kHz passes dry. A reversed
  one reads the render of its reversed file. The render is Swift's,
  offline, on the ramp render queue (§5.6, `IsolationRenderer`).
  **A retimed segment is isolated before it is retimed** (§11 AU-55 as
  amended, #387; `RetimedSound`). The tap adds no span for it. Its window —
  the frames it plays, padded and rounded out to whole seconds — is
  isolated, then crossfaded with the dry window at the amount into a file
  (`IsolationMix`; a voiced clip's voiced render takes its place, AU-145).
  A RENDERED segment (one with a `ramp`) plays the ramp render of that
  file, made through its own map counted from the window's first frame,
  and its dry render until that exists. A LIVE one (a constant speed with
  Keep pitch on) has the same source range of that file inserted in the
  media's place, counted from the window's first frame, and scaled as the
  media was, on a composition track of that file's format; until the file
  exists it reads the media.
  **The gate and the de-esser run after the noise reducer and before the
  compressor** (§11 AU-47), read at the compressor's lookup, with no
  latency. Their thresholds are dB relative to the clip's measured loudness
  (its `ClipLoudness` reading, §11 AU-41), resolved when the composition is
  built (`AudioDSPParameters.measured`, through `AudioDynamicsLevels`); a
  clip whose loudness is pending or unmeasurable gets neither stage, so a
  track whose only stage is an unmeasured gate earns no tap (AU-42).
  **The leveller runs between the gate and the de-esser** (§11 AU-66): a
  gain curve per clip and response (`AudioLevellerCurve`, the material's level
  per 10 ms played step relative to L) made beside L from the same reading and
  the clip's speech, resolved when the composition is built
  (`AudioDynamicsLevels.curves`); the tap applies the target and the limits to
  it at each step centre and interpolates per sample on the lookup frame
  (`AudioLevellerRun`), with no state and no latency, so block size, a seek,
  the preview, an export and AU-64's render agree. A clip whose curve is
  pending (no loudness, or no speech yet) or unmeasurable plays un-levelled.
  The order is isolation → voice → channels → EQ → hum → noise
  reduction → gate → leveller → de-esser → compressor → limiter → fader.
  **A voice effect rides the same pass** (§11 AU-142…AU-145): a segment
  whose clip has an `audio.voice` that is not inert and whose voiced render
  is READY as the composition is built (`CompositionBuilder.voicedAudio`)
  is a span at amount 1 — the render REPLACES the samples, in place of the
  clip's isolation crossfade, since a clip that isolates renders its voice
  from `dry + i·(iso − dry)` and waits for that file first (AU-143). The
  render (`VoiceRenderer`) is the clip's window through a fixed chain of
  Apple's units (`VoiceChain`: TimePitch → EQ → Distortion → Delay → Reverb,
  scaled by `amount`, with a per-kind makeup gain) at 48 kHz stereo in
  4,096-frame offline calls, the chain's latency discarded, cut at the
  clip's end and mono again as `(L+R)/2` for a mono source. A pending one
  plays without the effect (with its isolation, if that is ready); a
  retimed segment's voiced render covers its padded window, silent to the
  effect outside the frames the clip plays, and is retimed as above.
  **A composition audio track holds its envelope's value at its own first
  sounding segment (one whose source resolved; #217) from time 0** (Swift,
  `CompositionBuilder.volumeLegs`, #87), a second source format's track
  included, because AVFoundation starts a mix input at 1.0 and slews every
  volume change at full scale per 1200 frames.
  A gain change with sound on both sides on ONE composition track still
  takes up to 25 ms: the accepted limit, §11 #87.
- **`ducks`** (format version 29, §11 AU-113), only when the project has a
  speech duck: `[{"clip": id, "ramps": [ramp, …]}]`, one per SPEECH ducker
  (a clip's id, the inner clip's for a nested one), its own multiplier
  alone over its widened spans — the first span's start to the last span's
  release — in the ramps' shape above, or `[]` with no spans. Nothing
  builds a composition from it (every other track's `ramps` already carry
  the duck): the timeline draws it as the line on the ducking clip. A plan
  with no speech duck has no `ducks` key, so it is the text it was.
- **`gates`** (format 43, §11 CO-93), after `ducks`, only when a timeline
  clip has a `video.hide_silent` whose media has saved speech: `[{"clip": id,
  "ramps": [ramp, …]}]`, one per TIMELINE-level instance of a gated clip, its
  ramps tiling the instance's `[start, end)` in the handle's time and
  coalesced, each ramp's `from` read on the right of its start and its `to`
  on the left of its end — breakpoints at the instance's ends, every
  instance of the media's ends, each merged span's `s − fade`, `s`, `e`,
  `e + fade`, and the midpoint of two spans closer than `2·fade`. Nothing
  builds a composition from it (the recipe gates the opacity): the timeline
  draws it as the line on the clip. A plan with no gate has no `gates` key.
- **Instructions** tile `[0, duration]` with no gaps or overlaps (an
  AVFoundation requirement); a boundary wherever the set of visible
  layers changes — which includes every **inner** clip edge of a nest,
  since the invariant the tiling rests on is that membership at a span's
  first tick holds for the whole span. Hidden tracks contribute nothing,
  inside a nest as much as outside. `image`, `text` and `shape` clips
  need no composition track and do not appear in `required_track_ids`.
- The decoder budget: warn (in the plan, `"warnings": [...]`) when more
  than 8 video composition tracks are required by one instruction.
