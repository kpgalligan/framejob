# 7.8c Export — sound, the waits, GIF and APNG, graphics (continues §7.8)

Continues §7.8 (`07.8-export.md`: the rows, Quality and each codec's row) and §7.8b (depth, an HLG project, the deliverables, the frame's shape, what stops an export). The text moved here unchanged on 2026-11-09 (#424, the spec's ~500-line split rule), so an "above" or a "below" in it can point into the section's other files.

**WAV and AIFF.** Two uncompressed rows beside `audio_m4a`, for the file
you hand to somebody else's tool rather than the one you send: LPCM at
48 kHz, 16-bit or 24-bit (§11 AU-29), the master's samples (below) written
straight out, little-endian in a WAV and big-endian in an AIFF — the
CONTAINER decides the endianness, and `codec: "lpcm"` is what the writer
branches on to reach LPCM settings at all. Both are `video: false` with the
audio-only row's size list and the document's rate, and neither optimizes
for network use: a RIFF or an IFF file is a header followed by samples, with
no index to relocate. **`audio_bits`** is the depth: their preset rows list
`"audio_bits": [16, 24]`, their settings always carry it (16 when not
asked), a value that is not 16 or 24 is refused on any row `export
audio_bits must be 16 or 24, not {value}`, and a depth on any other row is
refused `{id} has no bit depth; audio_bits applies to audio_wav and
audio_aiff` — ProRes keeps 16-bit, as AAC and Opus are fed. 24-bit is packed
signed; both depths are rounded to nearest once from float, never dithered.
The sheet's Bit depth popup (16-bit, 24-bit) sits after Quality, live only
on these two rows; the footnote adds `24-bit`.

**Stems** (§11 AU-107, AU-108). The three audio rows (`audio_m4a`,
`audio_wav`, `audio_aiff`) list `"stems": ["tracks", "names"]` and take a
`stems` override: `tracks` writes one file per heard timeline track,
`names` one per set of heard tracks whose trimmed names match
Unicode-equivalent, ignoring case (#394), named by the first's spelling (an
unnamed track is its own). Heard is a track the plan labels an audio track
with (§7.2's `track`) that is not silenced by mute or solo among the
timeline's tracks. A stem is named by its track's trimmed name, else
`Track N` (its header's label), `/` and `:` written `-`, and ` (Track N)`
added to a name an earlier stem holds under the same comparison (then
` (Track N, 2)`, `, 3` and on while one still does); the
file is `<mix name> - <stem name>.<mix extension>` beside the mix, and an
existing file there is replaced without asking. The settings end with
`"stems": [{name, tracks}]` only when asked, in timeline order of each
stem's first track. Refusals: `{id} has no stems; stems applies to
audio_m4a, audio_wav and audio_aiff` on a movie row; `export stems must be
"tracks" or "names", not {value}` on any row; `stems: no track is heard, so
there is no stem to write`. The job (`ExportStemsPipeline`) writes the mix,
then each stem from a fresh build of the same plan on the export's key
reading only its composition tracks (`BuiltComposition.selectingAudio`),
one serial queue for the builds; a stem is PRE-MASTER — its tracks' sub-mix
as the mix plays it, with no loudness gain and no master limiter
(`ExportAudioMaster(limits: false)`), rounded once at the job's depth — so
the stems sum to the mix within rounding where the master neither gains
nor limits. A stem path naming one of the project's media (symlinks
resolved, case-insensitive) fails the job before any stem file is touched:
`The stem “{file}” would replace media this project uses; export under
another name.` Progress is `(finished + current) / (1 + N)` of the write's
share; a failure or a cancel leaves nothing the job wrote (the mix and each
stem are written to hidden siblings, and each stem is renamed over its path, then the
mix, only when every write has succeeded, so an existing mix and existing stems stay as
they were, §11 #531); the success line reads `Exported “Mix.wav” and 3 stems.`, the
footnote adds `3 stems`, and the `export_status` result lists each stem's
`{name, tracks, path}`. The loudness report is the mix's. The sheet's Stems
popup (None, One per Track, One per Track Name) sits after Bit depth, live
only on the three rows. A stem of a track with a compressor or limiter is its
sub-mix after them (below).

**Track and bus dynamics** (§11 AU-150..AU-154). A timeline track's
`compressor` and `limiter` run post-fader on its sub-mix, so every export
with sound reads its mix through `ExportMixRead`: when no timeline track in
the read (a stem's selection honoured) has either, the read is the one
`AVAssetReaderAudioMixOutput` it always was, byte for byte. Otherwise the one
audio reader carries one mix output per track with dynamics and one for
every other track read, each over only its own composition tracks' input
parameters (each tap in exactly one output); each group's buffers are placed
by stamp from the range's start at 48 kHz (a hole is zeros, an overlap's
covered head is cut), run through that track's compressor then limiter as
they arrive, the stage's 158-frame latency (a limiter's) dropped at the head
and flushed with zeros at the end, and `next()` hands on up to 4,096 frames
summed over the groups — read in step, from the group with the least
buffered, an ended group counting as zeros — to the master. The mix writer,
the stems, the WebM writer and the loudness measurement (float only for a
sub-mixed build) all read through it, so a track's dynamics are exact in
every file. The master chain is the loudness gain and the master limiter
below and nothing more (AU-154): a master bus compressor is the timeline
nested on one track with a track compressor.

**Loudness.** `loudness_lufs` (−70…0, BS.1770-4's own absolute gate at the
bottom) is the integrated target an export is normalised to, and
`peak_dbtp` (−20…0) is the true-peak ceiling of the export's master limiter
(§11 AU-27), −1 dBTP when absent. They are overrides on the bitrates' terms
— no preset carries one, each appears in the resolved settings only when
asked for, each is accepted by formats that cannot use it, and a value
outside its range or of the wrong type is an error naming it. Either may
come alone: the master runs with or without a target, so a ceiling alone is
its ceiling (AU-27 amended the pairing rule that refused one).

**How an export is normalised** (the Swift half; `Loudness.swift`,
`Exporter.swift`, `ExporterWriter.swift`). The measurement is BS.1770-4 —
two K-weighting biquads run continuously over the programme, 400 ms
gating blocks at 75 % overlap, the −70 LUFS absolute gate then the −10 LU
relative gate, and true peak through the standard's 4-phase 12-tap
interpolating FIR — with the coefficients transcribed from the
recommendation at its published 48 kHz and the meter REFUSING any other
rate rather than filtering with the wrong numbers. It is arithmetic over
plain float buffers with no AVFoundation in it, which is what lets it be
checked against synthesized tones: the EBU Tech 3341 cases are specified
signals, so the self-checks need no fixture file.

An export is therefore **two passes, and the first one runs on every
export that has any sound at all** — not only a normalised one. The final
progress line and the `export` tool's result both report what the file
actually holds ("Peak −1.0 dBTP · −14.0 LUFS"), which is what makes the
target a claim anyone can check rather than a number repeated back; the
price is one extra decode, about a tenth of a picture export's wall time
and roughly a doubling of an audio-only one's, and the progress sheet says
"Measuring loudness…" while it happens rather than sitting at 0 under a
label that claims it is writing. GIF and APNG measure nothing: those
containers hold no audio track, which is the same fact the core reports as
`audio: false`.

**An export's sound is exactly as long as its range** (spec §11 #337):
round(range × 48 000) frames, counted in order as the writer hands them on.
The buffer that crosses the range's end is cut there, every later buffer is
read and dropped, and a read that ends early is made up with silence up to
the end (`ExportAudioEnd`). The measurement reads only those frames. A read
that already ends on the range is written as it always was, so the
unnormalised byte-identity below still holds for it.

Pass 1 builds its OWN composition. An `AVAudioMix` copy shares the
`MTAudioProcessingTap` its input parameters hold, and a tap carries
per-instance state (the compressor's envelope, the noise reducer's delay
line), so two readers over one mix would interleave into one tap's state;
a second build costs one more pass on the build queue and removes the
argument. It reads **32-bit float**, because Int16 saturates and a mix
hotter than full scale is exactly the material loudness normalisation
exists for — its true peak would otherwise be pinned at 0 dBTP by the
decode rather than by the signal. Nothing in this tree had asked an
`AVAssetReaderAudioMixOutput` for float before, so the request is MEASURED
with `canAdd` and falls back to the writer's own 16-bit dictionary if it is
refused (measured on macOS 26.5.1: it is accepted). Pass 2 is the ordinary
write: every export, gained or not, reads the mix through the SAME float
dictionary the measurement read and goes through the master below, which
rounds once (rather than truncating, since truncation biases toward zero and
shows as DC on quiet material); the gain's rule is AU-28's, below.

**Every export goes through a master** (§11 AU-27..AU-29;
`ExportAudioMaster.swift`). Every export with sound reads the mix as float
(`ExportAudioMaster.floatMixSettings`, no 16-bit decode left), places each
buffer by its stamp (a hole fed as zeros, an overlap's covered head cut, as
CX-15 (5)'s `align`), multiplies it by the gain, runs `AudioLimiterStage`
(AU-20's detector and gain path, release 100 ms) at the export's
`peak_dbtp`, −1 dBTP by default and always on, and rounds once to 16 or 24
bits. The stage's 158 frames are compensated in the file — the stream's
first 158 output frames dropped, the last 158 flushed by `finish()` before
`ExportAudioEnd`'s padding — so output frame k is input frame k, and a mix
under the ceiling is written exactly as the float mix rounded: an
unnormalised export of such a mix is byte-identical to the 16-bit decode
before (`export_gain_proof.py`'s G1, per preset). The gain under the
master (AU-28): pass 1 also records 10 ms steps (`StepLoudnessMeter`), and
the gain is `AudioLimiterModel.gain` over them at the master's ceiling and
release, capped at +40 dB, rounded to the nearest 0.01 dB; under 40 steps,
or with no float read, the unlimited `target − integrated`. The report's
`integrated_lufs` is the model's figure at that gain, `true_peak_dbtp`
min(measured + gain, ceiling), `limited_db` how far the master took the
hottest peak down, and `capped_by_gain` when the +40 dB cap decided; a
non-finite measured peak keeps gain 0 and passes through unclamped.

What falls out of that is worth stating rather than discovering. Nothing
an export writes is clipped any more: a mix over full scale, normalised or
not, is held at the ceiling by the master, the file measures what the
report says, and the summary adds "· peaks limited by 8.6 dB" when the
master took 0.05 dB or more off. The master holds AU-22's accepted cases —
two limited clips overlapping, an action raising a clip above its base
volume, a nest clip above 1, #87's slew at a cut. The preview has no master
(S3): what it plays, and the Loudness Meter reads, is the mix before it.

**Where an exported sample lands** (§11 SY-23..SY-27, SY-39, #298). Every
export path places a source sample where the timeline says, within
`export_offset_proof.py`'s pin: |median| ≤ 1.0 ms and spread ≤ 0.5 ms over
sample-exact click fixtures for ×1, varispeed (keep pitch within ±0.1% of
×1 included, SY-39), LPCM and AAC sources, gain, pan, noise reduction
and range exports; |median| ≤ 5.0 ms for keep pitch outside 0.98–1.02,
whose `.spectral` drift stays open (#299); keep pitch in 0.98–1.02 outside
the varispeed band (`time_domain`) measured, not pinned (E35, SY-39); and
the video presets' clicks on their flashes'
timeline frames within 1.0 ms. Four causes were met where they enter,
in the composition `CompositionBuilder` builds for the export and the
preview alike: a non-48 kHz source is read from its 48 kHz copy (SY-23), a
time-scaled `off` segment and a noise-reduced track are placed by their
fixed leads (SY-24, SY-25), keep pitch within 0.999–1.001 (≠ 1) plays `off`
like keep pitch off, under 1.74 cents of pitch (SY-39), and keep pitch
elsewhere in 0.98–1.02 plays `time_domain` (SY-26, narrowed, not removed: E35). An MP3 source is
read past its own LAME/Xing encoder delay when Core Audio reports no
packet table, through the same copy, and pinned (SY-36); the preview's own output latency
is a manual check (SY-27). Those
pins are on click fixtures: on a real recording keep pitch's time-pitch
moves the sound against its timeline — it read −8.9 ms at ×0.99999, which
since SY-39 plays varispeed and R3 pins at 1.0 ms, and +94 ms at ×0.9 — so
`export_offset_proof.py`'s R4, R5, E34 and E35 are measured, not pinned
(SY-37). Every pitch-keeping method macOS offers was measured on that
recording at ×0.5–×2 (SY-40): `spectral` and `AVAudioUnitTimePitch` drift
by up to 97 ms (max − min) along a clip at ×0.9–×1.1, while `timeDomain` and the older
AUTimePitch stay within 10 ms of a per-rate lead (−41.6 … +7.5 ms and
+42.9 … +77.5 ms) — adoptable at 5.0 ms, none at 1.0 ms — so #299's
choice of method is its phase 2.

**A ramped clip's sound** (§11 SR-6, SR-12 (h)). An export waits, before
its composition is built, for every ramp segment of its plan that can be
rendered — its media resolves and its reverse, when reversed, is ready —
wanting those renders under its own key while it writes (`Exporter+RampAudio`)
and reading "Preparing…" meanwhile; so a ramp is never written silent, even
by an export asked for straight after the edit. A render that fails, or a
ramp segment with no cache folder to render into, fails the export
`rampAudioFailed`, naming the clip. An image sequence has no sound and does
not wait; a clip whose media is missing or whose reverse is pending is
slated and silent, and nothing waits for it.

**An isolated clip's voice** (§11 AU-57) is waited for the same way, in the
same wait: every isolated window of the plan (`IsolationCache.requests`) is
wanted beside the ramps under the export's key, so an isolated clip is never
written dry. A failed render, or an isolated clip with no cache folder to
render into, fails the export `isolationFailed`: "Clip N's isolated voice
could not be rendered: <why>."

**A voiced clip** (§11 AU-147) is waited for after that wait, in a second
one: a voice over an isolated clip is rendered from the isolated file
(AU-143), so its request (`VoiceCache.requests`) exists only once that file
does. All the export's renders are wanted again under its key and the
voices waited for, so a voiced clip is never written without its effect. A
failed render, or a voiced clip with no cache folder to render into, fails
the export `voiceFailed`: "Clip N's voice effect could not be rendered:
<why>."

**A cut-out clip's person masks** (§11 CO-6, CO-22 (e)) are waited for
first of all, in `Exporter.waitForMasks`, which `withRampAudio` calls BEFORE
its image-sequence guard, so a GIF or an APNG waits too. The windows are
every plan video segment of a clip whose base `video.cutout` is set, over the
export's range; the requests share every owner's open masks jobs by CO-22's
keep rule (a running one meeting the need, a queued one wholly inside it), so
the export waits on the document's own job rather than queueing a second
behind it, under a lane owner of its own (released by `releaseRecipeKey`).
The wait has no deadline but Cancel. No cache folder, an unreadable media or
a failed job fails the export `cutoutFailed`: "Clip N's person masks could
not be made: <why>.", N the first window's clip of that media; a media still
missing after a second landing fails it too ("its masks do not cover the
frames it plays"). The file is never written uncut.

These waits are `Exporter.withOfflineAudio`, which `withRampAudio` calls
after its image-sequence guard. Its second caller is the processed loudness
measurement (`ProcessedLoudness.render`, §11 AU-64 (d)): Loudness Normalize
and Enhance Voice render a clip's window through the very files its export
would use, under a key of their own, and an `ExportError` from a wait skips
that clip by name.

**A gated, levelled or de-essed clip's loudness** (§11 AU-42, AU-66) is waited for first,
before the renders, and a levelled clip's speech with it: a clip that plays
and whose level or leveller curve is still pending
(`AudioDSPParameters.pendingLevels`) holds the export at "Preparing…",
polled every 0.1 s off the main thread, for up to 300 s; then the export
fails `loudnessUnmeasured`: "Clip N's loudness or speech has not been
measured yet, so its gate, leveller and de-esser cannot be set. Wait for their
Status rows to show the clip's loudness, then export again." A cancel fails it
`cancelled`. A clip too short or too quiet to measure is not pending and
exports without those stages, as the preview plays it; so is a levelled clip
with no speech spans where speech detection is unavailable, which exports
un-levelled.

**GIF and APNG.** AVFoundation writes neither, so their rows resolve to
`avf_preset: null` — the signal to write the file frame by frame through
`CGImageDestination` instead of building a session — and to `audio: false`,
which is a fact about the containers rather than a choice about the
project. `file_type` is still the file's real UTI (`com.compuserve.gif`;
`public.png`, an APNG being a PNG carrying `acTL`/`fcTL` chunks), so the
save panel's content type and extension are right on either path. Both cap
what the project would otherwise supply, because their cost is frames ×
pixels and nothing else: GIF at 480 × 270 and 12.5 fps (a GIF frame delay
is a whole number of hundredths of a second, and 8 cs is the longest that
still reads as motion), APNG at 960 × 540 and 25 fps (true colour and
lossless, so it earns the extra pixels, and an `fcTL` delay is an exact
rational needing no such rounding). Both caps are defaults a size or fps
override replaces. On these two formats a size — the cap, a row of the
Size popup, a custom size — is a box the picture is FITTED inside, aspect
kept and never upscaled, where the movie writer writes exactly the frame
asked for, letterboxed (`AVVideoScalingModeResizeAspect`) unless the frame
is within a pixel of the canvas's shape and filled (above): padding a GIF costs
bytes in every frame for pixels that carry nothing, and a bigger frame
carries no more detail. The core does the fitting (`export_size.rs`,
applied by `rc_export_settings` and `rc_export_sizes` alike), so the Size
popup, the sheet's readout and the `export` tool all report the numbers
the file will have — a vertical 1080 × 1920 timeline's "GIF default" is
152 × 270 — and `ExporterImageSequence` draws each frame at exactly that
size rather than fitting a second time.

**Graphics** (road map 10's G3c; §11 G-8 and G-13). An export is handed
the document's compiled `GraphicSet` as it stood when the export was asked
for — by the sheet, a queued job (captured at ENQUEUE, beside the media
URLs), or the `export` tool — and PINS it on its own `RecipeSource` key for
its whole life (`GraphicRegistry.pin`, unpinned in `finish` and in
`deinit`), so a module saved mid-export, or a document edited or closed
under a queued job, cannot change what the file draws. Before the build it
runs the GATE: every graphic clip overlapping the range, and every graphic
clip of each nest reached from a clip in the range, however deep, whose
module did not compile
or is not in `graphics/` refuses the export before anything is written,
each named with its first diagnostic. Nothing is gated for an audio-only
row. The gate is compile-only; a frame that fails while the file is being
written records the failure on the export's key, the progress timer sees
it and cancels, and `finish` answers `.graphicFailed` — the graphic, its
frame and the message — and removes the file, whatever the pipeline had
answered. GIF and APNG pin the same set per frame and stop on a failed
report. An error card is therefore never delivered in a video. BOTH
cancels — the writer's and the loudness measurement's — only set a flag
their loops read before each sample; each reader is cancelled by its own
loop — each of the writer's two readers by its own pump, on its own queue,
after its own last read (§11 #378) — and the writer once every pump has left
its loop (`allInputsFinished`), because cancelling a reader under a running
read crashed the process (road map 10 §10.6 G3c). A read that never
returns is not woken (§11 G-17). An `ExportWriter` export with a pinned
set and a graphic in its range rasterizes its graphics ahead on worker
threads, and the compositor uses a worker's raster only on a pool miss
whose texture key matches its own, so the file is the serial path's
(§11 G-26).
