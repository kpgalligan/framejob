# 7.9a Agent — the tools

The agent lane, the helper, the assistant session and its tab are §7.9b; the
graphics loop, the dev tools and the transport are §7.9c (the dev tools continuing in §7.9k); `record_screen` is §7.9d; the app-state tools are §7.9e (continuing in §7.9l).

`agent.rs` is copied from Rasterize (generic streamable-HTTP MCP, tools
only). Catalog: one tool per §6 op with the same name and arguments —
**each of which also takes `scope`, the envelope key of road map 2's phase
9** (§6), injected from ONE line in `AgentCatalog.tool(...)` gated on the
core's own `rc_op_names`, so a new op gets it for free and cannot drift, and
enforced by a fourth part of the startup parity check, which is the only
mechanism in the tree that would catch an op tool declaring none.
**All sixty-nine op tools PRINT those arguments rather than
restating them** (road map 7's D3·3 for the clip group, D3·4 for the rest):
`AgentCatalog.opTool(...)` takes the
tool's prose and a sentence per argument and merges the structure — kind,
constraints, closed vocabulary, required list — in underneath from
`rc_op_schemas`, so **the core says what an argument IS and the catalog says
what it is FOR**. Where a tool deliberately accepts more or less than its op
does — a bare-string body, the string spellings of a boolean, a null that
MEANS something, a range the core clamps to rather than refusing, a default
taken from the playhead, the camera's focus from its cached person masks
(`switch_layout`'s `focus`, road map creator-jobs CO7, §11 CO-70), a list the
tool will not take empty, an argument
only the app can fill and so does not publish (the two graphic ops' and
`set_action_end`'s `schema`, read from the module's current revision, road
map 10's G3b and §11 G-34, `relink_media`'s `probe`, and `reframe_clip`'s `subjects`, read
from the analysis cache, road map creator-jobs VR2a2, §11 VR-28) — the
difference is a row of `AgentCatalog+Declarations.swift` with the op, the
argument, what the app adds and why, and the schema declares it, so an agent
can SEE a shorthand rather than discover it. What still declares a schema of
its own is the thirty-six APP-STATE tools, which have no op to read one from.

**`reframe_clip` waits for its analysis within a bound** (§11 VR-28). The tool first tries
the op with no `subjects`, uncommitted: any answer but the core's "clip {id} has no subjects to
follow; analyze it first" (VR-26's last refusal, last so every other one answers the trial)
goes straight to the edit, with no analysis. Otherwise it wants VR-12's kinds — `shots`,
`faces`, `subjects` — over the clip's window ± 1 s and waits up to CJ-25's 60 s, a Stop or a
failed job an error naming the kind and the media; once landed it fills `subjects` from the
cache (each `faces`-grid index both markers cover, boxes clamped into the picture, eight a
kind; `shots` the cut rule over the covered windows) and applies one step, "Reframe Clip",
answering `cached`. Past the bound nothing changes: the answer is `{ok: true, analyzing:
{media: [ids], covered: 0.4}, note: "Still analyzing the media of clip 12 (40 %); call
reframe_clip again to apply.", project}`, `covered` the share of the missing grid indices now
held, and the want stays held until every job has ended or the document closes.
`follow: cursor` never waits (§11 VR-50 (i)): after the trial's "no subjects" the first hop
finds the media's cursor file (`AutoZoom.cursorFiles`, its sentences the refusal for a missing
one), the file is opened and read off main (`FramingCursor.read`: CU-25's `path` at smoothing
0.5, each down click a `click: true` point, a point inside a typing stretch `typing: true`) in
place of the analysis, and the answer's `cached` is true.
`follow: speaker` (§11 VR-60 (c)) waits for the analysis as a following kind does, and the
last main hop adds `subjects.turns`: `SpeakerSwitch.read` over the `mics` clips (each its
track's speaker, no angle, no wide, the range the framed clip's span, the default settings),
then `SpeakerSwitch.turns` — SW-21's labels and SW-22 (a)–(e) on the labels themselves: the two
bridges, a person run of at least `min_turn` starting that microphone's turn and a crosstalk
run of at least `crosstalk_min` one turn per microphone active in it, each at `snap(onset −
lead)`, the first from the range's start, each ending at the next start. `read`'s problems and
SW-24's no-speech sentence refuse as "reframe_clip was refused: …" in SW-24's words; a call
addressed to a container other than the open one is refused ("follow speaker reads its
microphones on the open timeline; open that nest first with set_scope"); a microphone `read`
drops (its sound off) gets no turn, and the core names it. Each face box carries `mouth` (gap
÷ width) when its landmarks were read. Nothing is written to `media.speech` or a cache.

`set_video`'s `patch` is an Object, so a new property group costs prose in
`AgentCatalog+Properties.swift` and nothing in the argument half: the wheels
(§11 GR-11) are `{wheels: {lift|gamma|gain: {x, y, master}}}`, any subset
merging (`set_video {clips, patch: {wheels: {lift: {x: 0.2, y: -0.1}}}}` keeps
lift's master and the other two wheels), each −1…1 and the push inside the
unit circle, refused outside; the Wheels section's push, which has no typed
field, is exact here. `set_action_end {patch: {video: {wheels: …}}}` animates
them. The curves (§11 GR-12) are `{curves: {master|red|green|blue: [[x, y],
…]}}`: each channel 2–16 points, x strictly rising, x and y 0–1, refused
outside; a list REPLACES its channel, `null` removes it, and an identity curve
(every y = x, from x 0 to x 1) is stored as none. In `set_action_end {patch:
{video: {curves: …}}}` an identity curve is kept and animates the channel to
neutral, and an identity on either side is aligned to the other curve's x's;
two curves of different counts blend their values. The hue curves (§11 GR-32) are
two more channels, `hue_hue` and `hue_sat`: 2–16 `[hue, value]` points, hue
0 ≤ hue < 360 strictly rising, a shift −180…180 or a gain 0…2, every value
neutral the identity; `set_video {clips, patch: {curves: {hue_sat: [[0, 1],
[120, 0], [240, 1]]}}}` mutes the greens. The Curves section's points are the
same lists, written whole. The qualifier (§11 GR-13) is `{qualifier: {hue:
{center, width, softness}, saturation: {low, high, softness}, luma: {low, high,
softness}, invert, blur}}`, on an adjustment clip only (any other clip is an error
naming it): a range MERGES — `{hue: {}}` turns hue on at its default, a partial
range keeps the rest, `null` turns it off — the bounds refused, never clamped;
in `set_action_end` its numbers animate, the hue centre the short way round,
and a range turned on or off and `invert` switch at the end. The Qualifier
section's strips and fields write the same ranges, whole; Pick from Canvas's
pick is one `set_video`; `blur` 0–1 softens the weight by a Gaussian (GR-35), its Blur row the same key.

**A fifth part of the startup parity check holds that identity up**
(`AgentServer+Parity.swift`, road map 7's D3·5). For every op tool the
declared argument names must be exactly the core's for that op, plus the
injected `project` and `scope`, plus whatever a declarations row names, less
an argument a row says the app fills — in
both directions, so an argument the core has that no tool declares and an
argument a tool declares that no op has are each named with the op, the
argument and the side, and a declarations row naming an argument the core has
not got is named as stale. Because the catalog prints STRUCTURE and writes
only PROSE, the same part also complains about an argument that would reach an
agent with no description at all, and about a description written for an
argument the table has never heard of, which is how a misspelt prose key is
caught rather than dropped in silence. App-state tools are skipped by the same rule
part 4 uses — the core's own op list, which has no row for a tool with no op
behind it. **A sixth part** (`AgentServer.keyedToolFailure`, §11 CJ-13) holds
every tool `ModelKeys.keyed` names to be in the catalog with its key's clause
in its description ("Keyed (spec §11 CJ-3): where it would send to …"), and
names every offender. What no comparison of two lists can see is a
CALL. A call's KEYS are compared to the tool's published schema at the
dispatch — the argument gate, kpgalligan/framejob#21, for all one hundred and four
product tools — so a name no tool published is refused naming the tool and what it
takes, where it used to be dropped in silence; and that an argument the
catalog prints is one a hand-written handler really reads is put to the
running binary by `tools/proof/op_argument_proof.py`, one left-out argument
per op.

The scope is read ONCE per call, at the dispatch, and an op with no `scope`
of its own follows the nest the app has OPEN — a call and the window agree
about which
container they mean, or `get_project` would list clips the very next op could
not name. An EXPLICIT scope outranks the open view. The app-state tools are §7.9e (continuing in §7.9l), with the op tools `set_media_color` and `set_media_speech` and `set_audio`'s `duck.mode`; the op tool `set_media_cursor` is §7.9d's, with `get_cursor_events`.

**Lenient decoding is for what the CORE wrote; nothing a caller wrote is
decoded through it** (deepening D1): a patch, a colour, a region and a new
clip's text or shape go to the core as the caller's own object, and the core
is the one validator of what each may carry (§5.2, §6) — the agent door
checks only what the core cannot know, which is the target, the scope, an id
against the container it names, a time, and that a required argument was
passed at all.

Handlers use `performGroupedEdit` so off-event edits get their own undo group
(Rasterize's `AgentServer.performGroupedEdit`).
