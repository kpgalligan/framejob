# 4.3a Inspector — the tab strip and the Clip tab

The Clip tab's video, audio, text and shape sections are §4.3b; the Media, Document and Assistant tabs are §4.3c.

Tab strip across the top: **Clip, Media, Document, Assistant** —
`PanelTabsView`, all four always live. Clicking a clip anywhere shows the Clip
tab, including a click that re-picks the clip already selected; a selection
that changes any other way shows it from the Media and Document tabs only,
never from the Assistant tab (§11 AI-14). While the window's assistant waits
on an ask-first question, the Assistant tab's title wears a dot in the accent
colour, whichever tab shows (§11 AI-19). Multiple selected clips edit their
common properties together (one op with several clip ids).

It was six tabs — Video, Audio, Text, Shape, Media, Document — with a
disabled state per tab, a most-relevant-tab rule and a pin to defeat it. Four
of the six were about the same thing, the selected clip, and 304 pt gave each
about 50 pt of strip. They are now SECTIONS inside the Clip tab, and which
sections appear is a function of the selection's kind (`ClipPane.makeSections`)
— the piece of logic that replaces the whole tab-visibility apparatus. With
that, a pin protects nothing and is gone.

**Sub-tabs and the pinned block** (§11 CI-5; road map 9 §3). The Clip tab
is itself split into SUB-TABS, and above them, outside the scroll view, sits
one pinned block: the selection header, the action lane and a strip of the
sub-tabs, which stays put while the sections scroll — and, when every
selected clip sits on a matte track and those tracks share one mode, under
the strip a note on every sub-tab (§11 MT-7): "Matte for the track below
(<mode>). Not drawn: its blend mode, drop shadow and reflection have no
effect.", or, when none of those tracks has a target, "Nothing is behind this
matte track, so it cuts nothing."; every control stays live. When every
selected clip is an adjustment clip on a matte track the note is instead "An
adjustment clip on a matte track has no effect." (§11 GR-6). The tabs follow the
selection's kinds — **Text** for an all-text selection, **Shape** for an
all-shape one, **Picture** when a selected clip draws pixels and none is an
adjustment clip, **Color** after it when the selection has clips that draw and
every selected clip has source pixels of its own — media, image, still — or is
an adjustment clip; never text, shape, graphic, nest or an audio-only file's
clip (§11 GR-2, GR-6) — **Sound** when one has audio, and
**Clip** always, last — so a video with sound shows Picture · Color · Sound ·
Clip, a text clip Text · Picture · Clip, a shape Shape · Picture · Clip, an
adjustment clip Color · Clip and an audio file Sound · Clip. The first is the
default (Color never is, except for a selection with an adjustment clip, which
has no Picture), so a text clip opens on Text. A tab picked by hand is kept while the same
clips stay selected (selecting or changing an action keeps it) and is
forgotten whenever the selection's ids change. Each tab lists its own
sections: Text — Content, Font, Style, Outline, Backdrop, Box, Reveal,
Presets; Shape — Shape, Stroke, Fill, Gradient, Arrows; Picture —
Transform, then Crop, Corner radius and Chroma key for a source
with pixels of its own, then Shadow, Filters, Reflection, Spotlight,
Obscure; Color — Light, then Colour, then Wheels, then Curves, then Look (Light opens when none has a stored
preference), with Adjustment first and then Qualifier when every selected
clip is an adjustment clip (Adjustment then opens when none has a stored
preference); Sound — Volume, Fades, Duck, Noise reduction, Compressor, Mix;
Clip — Timing (or, for several media clips, its Reverse half), Speed for
media, Transition when the clip overlaps its predecessor, and Motion
presets for a clip that draws. The strip's cells are equal, square, 24 pt
tall with 8 pt above and below and 10 pt at the sides (the handoff's "8/10
padding", read that way); the active cell wears the selection fill and an
accent border, and a mono `◆N` in the action ink follows a label whose tab
the selected action keys — N counts the KEYS of the action's end patch
those sections write (§11 CI-6); Color's is 1 when the end holds
`video.color`, which Picture no longer counts (§11 GR-2), plus 1 when every
selected clip is an adjustment clip and the end holds `video.opacity`
(Strength, §11 GR-6); `video.qualifier` is one key however many of its ranges
the end names (§11 GR-13).

The Clip tab opens with a 44 pt selection header: an 8 × 26 pt tint chip in
the clip's kind colour, the name at 12 pt semibold, and a mono 10 pt line
giving the kind word, the duration in the DOCUMENT's timecode, and the
source's own facts. `ClipKindStyle` is the one mapping from a clip to that
chip, and the timeline bar and the timeline's own name strips read it too, so
the three views of one selection agree by construction.

Since format version 3 that name line is, for a SINGLE selected clip, an
editable field (`InspectorNameField`) showing the DISPLAYED name —
`ProjectSnapshot.name(of:)`: the clip's own name, else the fallback. Its
commit sends the trimmed text through `set_clip`, and an emptied field on a
clip with a name of its own sends `null`: this is the one place in the UI a
name is cleared back to the fallback, because the shared rename editor the
timeline uses for tracks, markers and clips drops an empty commit (a track
or marker name cannot be cleared). Emptying a field that already showed the
fallback sends nothing. A multi-selection keeps the drawn "N clips
selected". A label every selected clip shares draws as a 6 pt dot at the
line's right end — the strip's dot, so the two views agree — and the mono
line sits at y 27 under the 20 pt field.

Sections are disclosure groups with a reset-to-default in the header, a
right-aligned mono 10 pt summary of the group's current state (`100%`,
`neutral`, `+0.0 dB`, `off`) so a collapsed group still tells you something,
and per-section open/closed state in `UserDefaults`, keyed by the section's id.
Transform opens by default and the rest are closed; on any sub-tab where
nothing is open, the first section with no stored preference opens
instead, so a tab is never a wall of shut headers. A header darkens one
step under the pointer, since a click folds the group. The change fades
over 140 ms and is instant under Reduce Motion (§11 CI-15). Rows take no
hover.

**Row marks** (§11 CI-7 and CI-8; road map 9 §5). Every row starts with a
14 pt mark gutter that says what the selected action does to it: ◆ in the
action ink when the row writes a key the action's end patch holds (with a
mono "at end" after a discrete control, which switches rather than ramps),
○ when the row follows a keyed value (Gain follows Volume), ◇ faint when
ANOTHER action keys it (its tooltip names the action), and ⊘ faint when the
row writes the clip whatever is selected (Motion presets, pan, a list's
length). A keyed row's label is in the strong ink and its field and popup
wear a 1 pt action-ink border; ⊘ greys the label. A keyed slider fills in
the action ink from the value at the action's START to the knob, and a
coral tick marks the value at the PLAYHEAD when the playhead is inside the
clip; a field-only row shows that value as a "now" tag instead. Section
headers carry `◆N` (keys), ◇ and ⊘ after the title, a keyed section's
summary is in the action ink, and a section whose every writing row is ⊘
says "Actions don't animate this. Edits here change the clip." Selecting an
action opens the sections of the showing sub-tab that it keys. Every
sub-row — a shadow's Blur, a compressor's Ratio — carries the `mixed` badge
its parent row does when the selected clips disagree (§11 CI-15).

**Reset, Clear and the row menu** (§11 CI-9 and CI-10; road map 9 §7). A
section's Reset shows only while the section differs from its default, and
its summary is then in the body tier (`DS.textMuted`) rather than faint.
With an action selected, a section whose rows the action can animate shows
**Clear** in the same slot instead, and only while the action keys one of
those rows; it removes the section's keys from the action's end patch, so
the values fall back to what was held. On hover a keyed row's ◆ becomes a
× that removes that row's keys from the action ("Remove from action N").
Right-clicking a row opens its menu: "Remove from action N" on a keyed row,
"Go to action M" on a ◇ row (which selects that action), and "Set end value
to default" (with an action selected, on a row it can animate) or "Reset to
default", disabled when the row already holds its default. A refusal the
core writes for a person's edit is shown at the inspector's foot as
"Refused: " and the rule's own sentence until the project next changes or
the strip is clicked.

**Note on the section list.** The design handoff's table sketches five groups
(Transform, Video, Audio, Effects, Timing). What shipped keeps the panes'
EXISTING sections as the units and filters them by kind, because merging them
would have thrown away every per-section Reset button and every
evaluated-action note. The handoff's own implementation note asks for exactly
that — the rows move "largely as-is", and the work is the shell and the
kind-to-sections function.
Controls are Rasterize's `OptionControls` family: slider + field pairs
with quick-value chevrons, color wells, steppers.
