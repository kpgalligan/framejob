# 7.9i Agent — Make Vertical Version

The app-state tools are §7.9e; this file holds the one road map "creator-jobs" VR3a added (§11
VR-30…VR-37): `make_vertical_version`, the mirror of File ▸ Make Vertical Version… (§9, road map
creator-jobs VR3b). It sends nothing anywhere, so it needs no key (§11 VR-2, CJ-3). It is the
hundred-and-twenty-fourth product tool; it adds no op (`OP_COUNT` 70) and no format (43).

**`make_vertical_version {shape, follow?, zoom?, where_empty?, copy?, path?}`** — the top-level
timeline's 9:16, 4:5 or 1:1 version, made by `VerticalVersion.plan` (`VerticalVersion.swift`,
`VerticalVersion+Plan.swift`), the step File ▸ Make Vertical Version… and FC9 call too. It runs
off the main thread (`creatorOffMainTools`), never asks the person and reads no `UserDefaults`.
It takes no `scope` key.

- **Arguments.** `shape` is required: `9:16`, `4:5` or `1:1`. `follow` is `subject` (the
  default), `face`, `person`, `salient` or `center`; anything else is refused as "follow must be
  subject, face, person, salient or center, not <v>.". `zoom` is 1 by default (the core refuses
  outside 1–4); `where_empty` is `fit` (the default) or `center`; `copy` is true by default;
  `path` is read only with `copy`. There is no `captions` until VR4.
- **The size** (§11 VR-32). w = min(W, H) rounded down to even; h = 2 × round(w × r / 2), r 16/9,
  5/4 or 1: from 1920 × 1080, 1080 × 1920, 1080 × 1350 and 1080 × 1080.
- **The step** (§11 VR-33, VR-34). Each top-level clip with a picture is classed on the old
  canvas, first match: a "Blurred Background" behind a clip in front with the same source,
  start and duration; a full-frame shape plate or an image or still named "Background" at the
  old fill; a picture (a media, still or image clip covering one axis of the canvas at its
  first frame, at most 1 px inside, and centred within 2 % on the other or covering it); a nest
  by the same test; everything else. Then, on one trial: `set_canvas {width, height}` with no
  rescale and `add_track {index: 0, name: "Backgrounds"}`, each required; one `reframe_clip
  {clip, follow, zoom, where_empty, from_width, from_height, backdrop}` per picture, nest and
  other clip in id order, `from_*` the old canvas and `backdrop` that track — a media picture
  with `follow` (`where_empty` and the analysed `subjects` for a following kind), a media
  picture whose file is missing under a following kind with `keep`, a still or image picture
  and a nest with `center`, every other clip with `keep`; a refused op retried as `keep` and
  listed with the core's sentence, a refused `keep` stopping the step; then each backdrop
  deleted when its clip was framed with a follow other than `keep`, else re-filled with every
  image plate (`set_video {x: 0, y: 0, scale}` at the new fill), and a shape plate `set_shape
  {width, height}` at the new size; then `remove_track` of Backgrounds when no clip is on it.
  Swift restates none of `reframe_clip`'s refusals (§11 VR-26).
- **Treatments.** `followed`; `whole` — a following kind or `center` on a media picture that
  added a blurred copy and whose framing (k = s′/s, dx = x′ − k·x, dy = y′ − k·y) is the same
  at the clip's start, its last tick and every action's ends; `kept`; `refilled`; `removed`;
  `not_followed`. A followed clip's reason is "it is shown whole on a blurred copy where no
  subject is found" when a copy was added, then "moves by its own motion: <name>" for an
  active motion other than a fade or a spin, joined by " and ". A not-followed clip's reason is
  the core's sentence, or "its media file is missing, so it is kept as placed", "it is a still
  picture, so it is centred" or "it is a nest, so it is centred".
- **The copy** (§11 VR-30, VR-31). With `copy` the step is applied to CJ5b's derived document,
  handed the source's handle unchanged (every media, cache and analysis carried), as its one
  undo step "Make Vertical", named "<name> (9:16)", "(4:5)" or "(1:1)" until saved; with `path`
  it is saved there (as `save_project` saves). The source never changes and gets no undo step.
  With `copy: false` the step is applied to the project named, one undo step "Make Vertical",
  through `editResult`. A copy the step left unchanged is closed (its package at `path` removed)
  and the call refused: "Make Vertical did not apply to the copy, so nothing was made.".
- **The analysis** (§11 VR-37). For a following kind, `FramingAnalysis.requests` over the media
  pictures whose file is present, on the SOURCE and its cache. The wait is `reframe_clip`'s
  (`waitForAnalysis`, CJ-25's 60 s): past it nothing is made and the answer is `{ok, analyzing
  {media, covered}, note, project}`, the note "Still analyzing the media of N clip[s] (P %);
  call make_vertical_version again to make the version.". The subjects are read off main from
  the source's cache, so the copy carries the files and a later run reuses them.

**The answer**: `ok`, `canvas {width, height}`, `cached` (false when an analysis ran), `clips
[{clip, treatment, reason?}]` in clip-id order, `backgrounds` (the Backgrounds track kept),
`more_tracks`, `re_eased`, `moves_carried` (§11 VR-27 (f), counted only over clips framed with a
follow other than `keep`), `summary` (§11 VR-35: "Makes a W × H version." and the non-zero
counts, then one line per reason), `project`, and for a copy `carried {files, bytes, seconds}`,
with `path` `saved`. `copy: false` adds `editResult`'s `new_clips` and `new_tracks`.

**Refused, nothing made**, in this order: the target and each argument; an open nest
("make_vertical_version works on the top-level timeline: set_scope with no nest first."); `path`
with `copy: false` ("make_vertical_version writes path only for a copy: drop path, or copy.");
`path` held by another open project or being opened, then "<path> already exists, so
make_vertical_version did not write there: pass a new path."; a size the canvas already has
("the canvas is already W × H, so there is no <shape> version to make."); "Make Vertical was
refused at set_canvas: …" or "… at add_track: …" (the core's own sentence, the track cap
included); a core error for a bad argument (`zoom` outside 1–4), answered by a dry plan with no
subjects before any analysis is asked for; then, after the wait, a changed project or scope
("the project changed while make_vertical_version read the analysis, so nothing was made. Call
make_vertical_version again."), "Make Vertical was refused at <op> for clip C: …" for a step
that stops, and a copy left unchanged.

**The assistant** (§11 AI-7 as amended by VR-36): ask-first only when the call names `path`,
`new_project_from_range`'s shape; the question names where it writes.
