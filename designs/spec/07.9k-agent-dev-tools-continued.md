# 7.9k Agent — the dev tools, continued

Continues §7.9c's dev tools (compiled only under `FRAMEJOB_DEV_TOOLS`, §11 V-1): `land_recording`,
`cache_ledger`, `analysis_job` and `transcript_view`, moved here whole because §7.9c had passed the
spec's ~500-line split rule (#548, 2026-11-11). They were §7.9c's until then, so an older citation
of §7.9c for one of them means this file. The other dev tools and the transport are §7.9c.

**`land_recording {voice, movie?, door?, enhance?, place?, follow_wait?, cursor?, cursor_mode?,
show_clicks?, keys?, auto_zoom?, shortcut_overlays?, speed_up_typing?, camera?, camera_offset?,
camera_layout?, camera_cutout?}`**
(road map "audio" AP6 part 3, §11 AU-69 (e)) lands fixture files as a
FINISHED recording through the product's own code after the recorder's
`onFinish`, off the main thread. Without `movie` the files (1…8) are a
voice-over, one segment each; with `movie` one screen segment whose microphone
file is `voice`'s one file, `mic_offset` 0, and `cursor` (road map
"creator-jobs" CU3b, §11 CU-34 (d)), only with `movie`, a cursor file attached
to that segment's media through `MediaImporter.cursorAttachment` and
`RecordingSegment.withCursor(…, attached:)` before either door, as a
recording's landing attaches the file it wrote. `keys` (`off` or `shortcuts`) and the three
booleans `auto_zoom`, `shortcut_overlays` and `speed_up_typing` (road map "creator-jobs" CU10,
§11 CU-102 (c)) are the choice's Record shortcuts and "When it lands:" boxes, each only with
`movie` ("<arg> cannot be given without movie — a voice-over has no screen clips."), the three
refused after the `follow_wait` checks as `record_screen` refuses them (`recordingPolish`, `place`
read as true when absent, `keys` as `off`). `camera` (road map "creator-jobs" CO8, §11 CO-83
(c)), only with `movie` ("camera cannot be given without movie — a camera lands beside the screen
segment's movie."), is that segment's camera file, with `camera_offset` (integer ticks, default
0), `camera_layout` and `camera_cutout` each only with `camera` ("<arg> cannot be given without
camera — it applies to the camera's clips."), the last two checked as `record_screen` checks them
(`recordingCameraLanding`); the choice's `camera` is then the fixed id `land_recording`
(`AgentServer+LandRecordingCamera.swift`). Each file is probed with
`mayAsk: false`; the choice's `enhanceMicrophone` is `enhance`, its
destination `record_screen`'s. `door: "tool"` (the default) waits out a drag
and runs `landAndEnhance`, answering what `record_screen` would; `door:
"panel"` calls the recorder panel's `recordingEnded(.success)`, waits up to
25 s for the panel to be idle, then polls `RecordingEnhance.isUnderWay` (the follow's timer or
its measurement, §11 #546) and
`RecordingPolish.isPending` every 0.5 s for up to `follow_wait` seconds (0…330, default 0), and
answers `{landed (document, new_project or null), note (the panel's), project,
enhance_pending (`isUnderWay`), polish_pending (read last)}`. Refused by name: a path that will not probe,
`movie` with other than one voice file, `place` with the panel door, the
panel door while the recorder or the panel is not idle, `follow_wait` with
the tool door or outside 0…330, `cursor`, `cursor_mode`, `show_clicks`, `keys`, the three
polish booleans and `camera` without `movie`, `camera_offset`, `camera_layout` and
`camera_cutout` without `camera`, and a cursor file
that does not attach (its sentence after "land_recording: "). It mirrors no edit of its own — the landing
and the follow-ups are the doors' — and is `audio_ap6c_proof.py`'s, `cu10_proof.py`'s and
`co8_proof.py`'s instrument:
the recorder needs the Microphone grant and a voice, which a proof's instance
does not have.

**`cache_ledger {project?, gate?, seconds?}`** (§11 #552) answers the cache ledger's dev side
for a document's cache folder, on the main thread and at once: `{ok, cache, save_waits:
{writer: n}, gate: {writer: armed | waiting | save | timeout | disarmed}}`. `save_waits` counts,
per writer (`thumbs`, `peaks`, `loudness`, `sync-features`, `speech`, `device-transcript`,
`ramp-audio`, `isolated`, `voiced`, `analysis/<kind>/<media>`), the publishes since launch that
found a save of the package in flight and waited it out. `gate` (an array of writers) replaces
the folder's armed set: each named writer's next publish is held until a save of that folder is
inside its `-RCDevSaveHold`, `seconds` pass (above 0, at most 600, default 60; refused without
`gate`) or a later call leaves it out; `[]` disarms. It mirrors no edit and is
`save_hold_proof.py`'s instrument.

**`analysis_job {project?, media? | clips?, kind?, from?, to?, wait?}`** (road map
"creator-jobs" CJ2a, §11 CJ-27) stands in for a document's command owner in a
proof, because the server answers one request at a time and no call can
overlap a held `get_media_analysis`. Off the main thread. With `media` (then
`kind` is required, the window as `get_media_analysis`'s `media` form) it wants
that window's missing ranges under the document's dev owner — one per document,
alive while it is open, each want passing its earlier requests too — and
returns at once; with `clips` instead (§11 VR-16) it wants every
`FramingAnalysis` request of those clips (VR-12: each played window ± 1 s, in
`shots`, `faces`, `subjects`) the same way, answering `wanted: {project, clips,
requests}`; with `wait` (seconds, 0…`AnalysisLane.callWaitLimit`) it then
waits until every dev-wanted job has ended. It answers `{ok, now, wanted:
{project, media, hit}?, jobs: [{project, media, kind, ranges, save_waits, queued_at,
started_at?, ended_at?, outcome?}]}`, every request a dev owner wanted since
launch, from the lane's runs, `save_waits` the publishes of that cache, kind and media
that found a save of the package in flight and waited for it (§11 #429), `now` the process uptime, `lane_queued` the
requests the lane has queued since launch (never falling, VR-16); and `mask_wants:
[{role, owner, media, ranges, wanted, outcome?, error?, queued_at?,
started_at?, ended_at?}]` (§11 CO-22 (h)), every want a cutout made — `role`
`document`, `export` or `frame`, logged once per (role, owner, request), the
last 512 kept — `wanted` true while that owner wants it now, always present;
without `media` it targets no document. Its launch defaults: `-RCDevAnalysisHold <s>` holds each
analysis job before its first frame, polling cancellation every 50 ms, and
`-RCDevAnalysisCanned YES` lets a canned marker answer (CJ-26). It mirrors no
edit and is `analysis_proof.py`'s instrument (A5–A7, A11) and spike CJ-S3 (b)'s.

**`transcript_view {project?, focus?, select?, click?, select_pause?, wait?,
words_from?, language?, stop_after?, read?, find?, find_step?}`** (road map "creator-jobs" TX2a, TX2b, TX3a
and TX3b, §11 TX-23, TX-27, TX-31, TX-34; Find, #434, §11 TX-38) is what a window's Transcript tab (§4.3e) and its bar show, and
what a person does there: `words_from` (a track id of the edited container,
or null for All tracks) and `language` (an installed recognition language, or
null for Automatic) set the bar's two popups through their own paths; `read`
presses Read; `focus` makes the view first responder, `select` (`[first,
last]` token indices, inclusive; null clears) selects as a person does — the
selection widened and its cut made the in/out range (TX-31) — `click`
takes the mouse's path (that token selected, the playhead to its frame-snapped
start, playback going on), and `select_pause` (an integer ≥ 0) clicks pause i as
a person does (it alone selected, its cut the in/out range, the playhead to
the cut's start, TX-34), in that order; `stop_after` (0–60 s) schedules a
press of the bar's Stop, through its own path, on main that many seconds
after the answer — every tool call holds the agent lane's one lock, so no
call could press Stop while `get_timeline_transcript` waits; then it polls
every 0.05 s for up to `wait` seconds (0–60, default 0) until the tab's
source is settled. Off the main thread, every step an `onMain` hop. It
answers `{ok, settled, tokens: [get_timeline_transcript's word rows, the tab's
own `cut_start`/`cut_end`, + {index, paragraph, struck}], paragraphs: [{index,
start, timecode, first_token}], highlight, playhead, playing, selection, cut:
null | {selection: [first, last] widened, start, end, clips_after,
clips_peak, refusal: the sentence Delete would refuse with, or null} | {pause,
start, end, clips_after, clips_peak, refusal} with a pause selected, pauses:
[{index, after, start, end, cut_start, cut_end}], pause_selection: int | null,
first_responder, fill: {media,
fraction} | null, owns_want, status (idle, loading, reading, no_model,
failed or stopped), status_text, no_words, notes, rebuilds, last_rebuild_ms,
top_token, bar: {words_from, tracks: [{id, name}], language, languages:
[{identifier, name}], stop_shown, read_shown, stop_after: "pending" |
"pressed" | "not shown" | null}, project}`. Refused, before anything moves: a
project with no window, a Transcript tab not shown ("select_inspector_tab
{tab: "transcript"} first."), an index past the tokens shown, a track not in
the container ("words_from names track N; Words from lists …."), a pause past
those shown ("select_pause names pause <i>; the tab shows <n>."), more than one
of `select`, `click` and `select_pause` ("select, click and select_pause each set
the selection: pass one."), a language
`transcribe` would refuse, `select`, `click` or `select_pause` together with
`words_from` or `language`, `read` together with `words_from` or `language`, `stop_after`
while Stop is not shown and `read` while Read is not shown. **Find (§11 TX-38):** after `click` or
`select_pause` it applies `find` — a string opens the find bar as Edit ▸ Find… does, its field first
responder, and sets the field's text through the field's own change path; null closes it by Esc's path —
then `find_step` (`"next"` or `"previous"`, Return's or ⇧Return's path, once). The answer's `find` is null
while the bar is closed, else `{query, count, current: int | null, matches: [{first, last}] (the first
200, token indices), label: the bar's count, field_first_responder, current_visible}`. Also refused:
`find_step` with the bar closed and no `find`, or with `find: null`. It mirrors no edit (the tab is view state) and is
`transcript_tab_proof.py`'s and `transcript_find_proof.py`'s instrument.
