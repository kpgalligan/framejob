# 7.9e Agent — the app-state tools

The op tools, their parity check, the argument gate and lenient decoding are §7.9a; the agent lane, the helper, the assistant session and its tab are §7.9b; the graphics loop, the dev tools and the transport are §7.9c (the dev tools continuing in §7.9k); `record_screen` is §7.9d. The app-state tools — every tool that is not an op — follow, with the two op tools whose text sits among them, `set_media_color` and `set_media_speech`, and `set_audio`'s `duck.mode` (the three that read or want a media's on-device analysis — `get_media_analysis`, `split_at_shots` and `analyze_cutout` — are §7.9j):

`render_frame`, `normalize_clip`, `enhance_voice`, `match_audio`, `sync_audio`, `export`,
`export_status` and `cancel_export` are §7.9l, moved there unchanged on 2026-11-11 because this
file had passed the spec's ~500-line split rule (#585).

`set_scope {nest?, clip?}` (the mirror of the double-click and Clip ▸ Open
Nest, and what lets `render_frame` and `get_project` look inside a nest at
all; `clip` is the precise spelling, since a nest may be shown by two clips
at two different starts, and neither argument means the timeline),
`open_project {path}`, `new_project {path?}` (ask-first for the assistant only with `path`, §7.9b), `import_media {path}` →
media id (a `.cube` LUT, §11 GR-8, answers kind `lut` and a note naming
`set_video {clips, patch: {look: {kind: "lut", media: N}}}`, and `add_media`'s
descriptor defaults `has_video` true only for a video or an image; a folder,
§11 #497, imports the media files directly inside it as one undo step and
answers `{folder, imported, skipped, note, project}` — `imported` in Finder
order, each a file's fields with its `media`, and `skipped` each `{path,
reason}`: `not a media file`, `a folder`, `a package`, `already in the media
list` or the probe's sentence — or refuses `Nothing in <name> was added: it
has no files directly inside it.`, `Nothing in <name> was added. Skipped:
<file> (<reason>); ….` or, for a folder whose items cannot be listed,
`Nothing in <name> was added: it could not be read.`), `save_project` (it and `new_project {path}` refuse a path another
open project holds, naming that project, §11 #40), `new_project_from_range
{from, to, path?}` (road map "creator-jobs" CJ5b, §11 CJ-51, CJ-52, the
hundred-and-tenth product tool — the mirror of File ▸ New Project from
Range…: off main, one main hop; refused while a nest is open, onto a path
another open project holds (§11 #40) and where anything already exists; then
`ProjectDocument.derived(…)` opens `keep_range {from, to}` of the target's
handle as a new document, untitled and dirty named "<name> (range)", or saved
at `path` first, with the kept media's caches and the drawn graphics, fonts
and assets carried (§5.6); it answers `{project, saved?, carried: {files,
bytes, seconds}}`; the target never changes and gets no undo step; no
`scope`; ask-first for the assistant only with `path`, §7.9b; the dev-only
`-RCDevDerivedHidden YES` opens it with no window), `close_project {discard?}`
(File ▸ Close, §11 #40: refused while a sheet is open on the window, and
with unsaved changes unless `discard: true`; it writes nothing, and a later
call naming the closed path is refused), `get_project` → the JSON, `set_playhead`,
`set_range`, `set_selection` and `undo` / `redo` (the view state and the
history are app state, not ops, but without a setter for each the "one
edit is one undo step" and "the in/out range scopes the export" properties
cannot be checked by driving the built app),
`import_captions {path, track?}` and `consolidate_media {}` (M3's two
§5.6 file features). The op tool `set_media_color {media, color}` (§11
GR-16, the ninety-first product tool) mirrors the Media tab's Camera Log
popup: `color` reaches the core unread (`setMediaColorRaw`), which answers
every refusal in its own sentence, and an absent `color` is the one thing
the handler names; `get_project`'s `media[].color` shows what import
detected. Copying a clip carries its media's Camera Log LUT row with it, so a
paste lands the conversion remapped. The op tool `set_media_speech {media,
spans}` (§11 AU-110, the hundred-and-fourth product tool) is the spans Duck by
Speech saves on a media: `spans` reaches the core unread. `set_audio` reads
one key of its patch, `duck.mode`: `speech` prepends `DuckSpeech.ops` — a
`set_media_speech` for each media without spans, from its voice cache — in
the same undo step, and its refusal (not a media clip with sound; speech not
detected yet) is the tool's error (AU-111).
For `transcribe(engine: "assemblyai")`, the handler validates typed arguments
and the target before the coordinator decides whether a keyless run can reuse
every packaged transcript. Keyless calls resolve no endpoint; a mixed or stale
batch is refused as a whole with no request or edit. Successful placement is
one grouped undo step, and `place: false` only returns cues. Deferred remote
deletions are named in `note` on success and in the error on failure.

`record_screen` (File ▸ New Recording…'s mirror) is §7.9d.

`detect_silence {clips?, mode?, voice_confidence?, threshold_db?,
min_length?, padding?}` → the
quiet spans of the timeline and the scope they were taken over, which
`ripple_delete_ranges` then cuts — like `detect_fillers` and
`get_transcript`, a tool that reads a CACHE rather than the model and
neither edits nor moves anything (it is the sheet's own detector, so an agent and Clip ▸ Remove
Silences… propose the same cuts). A moment is quiet where every clip in
scope is quiet there, measured as the file's peak times the mix envelope
(§7.2), and two things are never in a candidate: a clip the mix has
SILENCED, which is dropped from either scope rather than read as quiet —
it covers its span while passing the test at every tick, so a muted music
bed would otherwise propose one cut across the whole song and take the
voiceover under it — and a NEST, whose sound counts toward the test but
which no candidate may intersect, because `Source::Nest` has no in point
and splitting a nest clip strands its tail (the dead air inside one is
reached by opening it, ⌘↓ or `set_scope`; §4.4's round trip still works;
each nest clip a quiet run of at least `min_length` crossed is named in the
result's `protected_nests`, ascending, with a note to `set_scope` into it
and call again — the run is measured on the scoped clips, so the nest
itself may hold no dead air there). A ramped clip is read through its plan audio
segment's source map (§11 SR-20 (d)). `mode` is road map 4's S1 — `voice`, the
default, judges by the cached Silero VAD probability against
`voice_confidence` (0.1–0.9, default 0.5, refused in `level` mode) and falls
back to the level rule over any clip whose own source window holds no voice,
naming those media in `judged_by_level` and those clips in
`judged_by_level_clips`; a media whose speech cache has not
landed is named in `voice_pending`, is never quiet BY THE MODEL and is not
judged by level either — though the mix's own gain floor can still make it
quiet, which is why the note beside `pending_peaks` promises nothing about a
media this answer already proposes a span inside, and names a clip the mix
alone made quiet while its analysis runs in `proposed_by_mix_clips` (#107) —
and is folded with the waveform waiters into `pending_peaks`,
`detect_fillers {clips?}` (cut-by-transcript CT-2, §11 TR-4, TR-7, TR-9) → the
filler words of the timeline's speech as ranges, which `ripple_delete_ranges`
then cuts — the read half of Clip ▸ Remove Filler Words… (CT-3, §11 TR-10), whose
Remove sends its ranges to `ripple_delete_ranges`, and the agent's path; like
`detect_silence` it edits nothing. It reads only a cached
AssemblyAI transcript whose marker serves `.fillers` (`FillerDetector.swift`),
never the network, and names any media in scope without one under
`needs_transcript` with the TR-7 note, which names `transcribe_for_fillers`. A ramped
clip's words are placed through its source map (§11 SR-20 (d)). A run of consecutive fillers is widened
outward to the 32 ms Silero grid within the words beside it, then snapped
inward to the frame grid (TR-9); `fillers` lists each kept run's clip, words
and range, `ranges` merges them, and `dropped` names a run too short on both
grids, one overlapping a word of another clip on any unlocked track, one
crossing a nest clip and one reaching an overlap between two clips on one
unlocked track, with a stored transition or without one, or the area around
it, as wide again as the overlap on each side, each with its reason. A
clip on a locked track is not read and is named under `locked`, and a media in
scope whose file is missing is named in the `note` with `relink_media`. Omitting
`clips` reads the selection when it holds a clip with speech from a media
file, every clip otherwise, and `scope` says which,
`transcribe_for_fillers {media}` (CT-3, §11 TR-2, TR-10) → the Transcribe button
of a Clip ▸ Remove Filler Words… row: one media re-transcribed with AssemblyAI with
its previous request (the marker's language, speaker labels and vocabulary;
detection, none and none without one) plus the shipped models, `disfluencies:
true` and `refresh: true` (`FillerTranscription.swift`), off the main thread, so
`detect_fillers` can read its fillers. It writes only the media's transcript
cache: no caption is placed and no undo step is made. It answers `ok`, `media`,
`ready` (whether `FillerDetector.fillersFile` now reads the media) and `project`
beside `transcribe`'s cloud fields (`engine`, `language`, `uploaded`, `cached`,
`audio_seconds`, and `speech_model_used`, `language_detected`, `endpoint` and
`note` when they apply). It is refused, in this order, for an unknown `media`,
a document with nowhere to keep its transcript cache, a media whose file is
missing, a media no clip plays from its file, and no credential (`ModelKeys.refusal(.assemblyAI)`, the keyed
refusal at the point it would send, after the ready arm, §11 CJ-12); a failed run
answers `transcribe`'s failure sentence with what was billed. A media that
already has a filler transcript makes no request and answers `ready: true`,
`uploaded: []`, `cached: [media]`, `audio_seconds: 0` and a note. It is always
withheld from the assistant (§11 AI-7 as TR-10 amends it),
`get_transcript {clip, language?, from?, to?}` (CT-4, §11 TR-5, TR-11, TR-13, TR-14) → one clip's spoken
words in TIMELINE ticks, ready for `ripple_delete_ranges`: the words File ▸
Generate Captions… and Clip ▸ Remove Filler Words… read, handed to the caller —
the assistant's path to a false start. The source is the media's cached
transcript when its marker serves `.captions` (`TranscriptReader.cached`,
through `FillerDetector.transcriptFile`), mapped by R6-10's
`MediaTranscript.words(for:in:)`; else this Mac's recogniser over the clip's own
window (`TranscriptReader.recognize`), its words stored as media source ticks,
kept by R6-10's half-open source-window test and mapped by
`MediaTranscript.project`; never the network. A ramped clip's window and words follow
its source map, the 2 s pad below read as source (§11 SR-20 (d)). What the recogniser heard is
cached per media and language in `cache/device-transcripts/`
(`DeviceTranscriptCache`, TR-14), keyed by the file's four-field source stamp,
the language, the OS version and the format `version`, and read by `get_transcript` alone: a call whose
span is inside a stored run answers from it without recognising again. Each on-device word's start is
moved, as it is read, to where its sound begins — the media's voice cache refined on its peaks
cache (road map "creator-jobs" TX1b, §11 TX-15, TX-16) — and the window test reads the moved start;
the stored run is unchanged, ends are as heard, and with no voice cache yet the starts are the
recogniser's and `note` says so (TX-18).
`language` applies to the recogniser only, matched by `transcribe`'s own two
functions. `from` and `to` (TR-13) are optional timeline ticks, snapped to
frames by `optionalTimeArg`, a missing one the clip's start or end: the window
[from, to), clamped to the clip, keeps only the words that overlap it
(`TranscriptReader.overlapping`), a word across an edge answered whole with its
own times, and an on-device run then hears only the window and 2 s of source on
each side, clamped to the clip (`TranscriptReader.recognitionJob`). It answers
`ok`, `clip`, `media`, `engine` (`assemblyai` or
`apple`), `language` (omitted when unknown), `fillers_reported` (whether the
transcript was asked for fillers: false for every on-device run), `cached`
(engine `apple` only: whether the words came from a stored run), `count`,
`words` (`text`, `start`, `end`, `filler` by TR-8's rule, and `speaker` when
known, sorted by start then end), `from` and `to` (the window as applied, only
when the call gave either), `note` ("No words were heard in clip N.", or "No
words were heard in clip N between F and T ticks." for a window, and the
sentence that a filler may be missing when `fillers_reported` is false) and
`project`. It is refused, in this order, for the clip (`clipArg`), a clip
`Transcriber.jobs` refuses ("Clip N has no words to read: <reason>."), a `from`
or `to` that is not a time, an empty window ("to must be after from: …"), a
window outside the clip ("The window … is outside clip N, which plays from S to
E ticks."), a misspelt language, then — with no cached transcript — the uninstalled model and
the recogniser's own sentence. It runs off the main thread, and the assistant's
Stop reaches its on-device run ("The transcription was cancelled.", AI-16 as
TR-11 amends it). It edits nothing and makes no undo step,
`transcribe {clips?, language?, place?, engine?, speakers?, vocabulary?,
refresh?, style?, replace?, slide?, fill?, dim?}` and `export_captions
{track?, path, format?}`
(road map 2's phase 4 — the mirrors of File ▸ Generate Captions… and File ▸
Export Captions… — with `transcribe`'s `engine` … `refresh` road map 6's C1
and `style`/`replace` road map 8's W4a). `style` is `subtitles` (the
default, today's cues) or one of the five word caption styles —
`highlight`, `pill`, `karaoke`, `build`, `one_word` — a misspelling refused
with the six named; under a word style each result cue adds `words`
(`[{start, end, text}]`, timeline ticks) and `size` where a lone word
shrank, and the placed pages carry the style's face, `case`, `word_style`
and the words in clip time. `replace: true` removes, in the same undo step,
every caption track this command could have made over the scope (named
"Captions" or "Captions N", only text clips, each overlapping a clip being
transcribed) and the result lists them under `replaced` whenever `replace`
was given; it is refused by name with `subtitles` or with `place: false`.
`slide`, `fill` and `dim` (issue batch B86, §11 W-15) are three booleans,
each false by default and never what the sheet last chose, that add a look
to the pages placed: `slide` writes `active_pill.glide` (style `pill`),
`fill` writes `active_fill` (`highlight`, `karaoke` or `build`) and `dim`
writes `pause_dim: 0.5` (any word style). A `true` with a style it shows
nothing on, or with `place: false`, is refused by name — `slide only
applies with style pill — not karaoke.` — after `replace`'s refusals and
before the scope; an explicit `false` is always accepted, where `replace`,
`speakers`, `vocabulary` and `refresh` are refused on presence. A placed
run in which any of the three was given answers `looks`, the names that
were on.
With no `clips`, `transcribe` reads only the clips that can be heard (§11
TX-35): a clip with recorded sound that is muted, on a muted or soloed-out
track, or turned down to nothing is left out, and with nothing heard it is
refused by a sentence that says to name a clip; a clip named in `clips` is read
muted or not.
`transcribe` returns the cues in TICKS whether or not it placed them —
`place: false` is a read, like `detect_silence`, and registers no undo
step — and reports every named clip it could not read under `skipped`.
A ramped clip's cues follow its source map; cues made before a ramp edit are
not re-timed by it (§11 SR-20 (d), (g)).
It has TWO engines. `engine: "apple"` is the default and is the on-device
recogniser; `engine: "assemblyai"` uploads the WHOLE audio of every media
file behind the named clips to AssemblyAI, and `speakers`, `vocabulary` and
`refresh` apply only to it — each refused BY NAME under `apple`, because an
argument that cannot do anything is a mistake and not a no-op. With
`speakers: true` and style `subtitles`, each speaker's cues are placed in
their own colour, white, yellow, cyan, green by first appearance (§11's
R6-22). The default
is never what the sheet last chose (§11's R6-2). The refusal ORDER is the
caller's own mistakes first — an unknown clip, an empty scope, a misspelt
`engine` with both spellings named, a cloud-only argument under `apple` —
then the credential, and only then the network. Every pair's precedence, the
hold and the ten-hour limit included, is §11's R6-17. (**Corrected 2026-09-21** by
road map 6 §10.13's reader review, which also corrected §5g's twin sentence:
this used to name "a media over AssemblyAI's ten-hour limit" between the
credential and the network. That limit is not a position in a RUN's order —
it is one MEDIA's problem, checked at the head of its own fetch and therefore
after every earlier media's whole round trip, and reported under `skipped`.
It refuses the run only when it is the only media there is. MEASURED.) The cloud result gains `engine`, `uploaded` and `cached`
(media ids), `audio_seconds` (what was billed), `speech_model_used`,
`language_detected` with its confidence, `endpoint` (the host alone of the
server a keyed run's requests went to, absent when no credential was found;
#94), and `note` when there is something to say — a vocabulary that was
capped, R6-8's fallback, a remote delete still owed, or a fetched transcript
that could not be kept for reuse. The on-device engine
(`SpeechTranscriber` since road map 8's W2,
§11 W-8) needs no grant and has no length ceiling, so its result carries no
`truncated` and no `note` — neither engine's does. Its models are installed
per Mac: a language whose model is not installed is REFUSED by name ("a
person has to install it"), and the tool never downloads one — a download is
a person's act, from the sheet's Download row. `export_captions` never guesses its track: with no all-text track,
or more than one, it refuses and lists the candidates by id and name — the
posture `remove_media` and `export` already take when an answer is not
unique — and it edits nothing, so it registers no undo step either. Its
`path` keeps every extension but `srt` and `vtt`, which the format's own
replaces (`chart.png` → `chart.png.srt`, the save panel's rule, §11 #43).
