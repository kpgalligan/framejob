# 7.9c Agent — the graphics loop, the dev tools and the transport

The op tools, their parity check and lenient decoding are §7.9a; the app-state tools are §7.9e; the
agent lane, the helper, the assistant session and its tab are §7.9b; `record_screen` is §7.9d.

**The graphics loop** (road map 10's G4a): `write_graphic {name, source}`
writes `graphics/<name>.js` through the store's one writer (atomically,
creating the folder), rescans at once and answers the compile of THAT text —
`ok`, `meta`, `schema`, `diagnostics [{level, message, line, column,
frame}]`, `clips` — where a module that does not compile is an answer, not
an error; the write is not undoable and never dirties the document (G-3),
and a bad name is the core's sentence. `get_graphic {name?}` reads one
module back (its source, revision and compile) or, with no name, the folder
— its path whether or not it exists yet, and every module with its revision,
`ok` and `clips`. `graphic_reference {}` answers the bundled
`GraphicsAPI.md` verbatim and needs no open project; a `project` it is
given must name an open one, or the call is refused with the sentence every
tool uses, "No open project is at …" (spec §11 G-20 (e)). `get_project` gains
`graphics: [{name, revision, ok, clips}]`, always present. The reference is
also written into an EXISTING `graphics/` as `API.md` and `API.d.ts` (never
a reason to create the folder, G-14, and not content that makes an untitled
root worth carrying). `get_graphic {}` also lists `families` (the engine's own
names, `rc_graphic_library_families`) and `assets`.
A module that compiles answers its top-level warnings (what `__warn` collected
while its top level ran, e.g. `asset("x")` outside `render`) as its
`diagnostics` in both `write_graphic` and `get_graphic {name}`, with `ok`
still true; and `get_graphic {}` answers `warnings`, always present: what the
folder's scan skipped or could not watch, in its own sentences (spec §11 G-24
(a), (b)).

G4b adds three. `render_graphic {name, frames | frame, props?, width?,
height?, max_width?, background?, format?, path?}` (ask-first for the
assistant only with `path`, §7.9b) draws a module WITHOUT a
clip, on the server thread: the ctx a clip would get (the canvas's fps,
`durationInFrames` from `meta` else 5 s, the size from the arguments, else
`meta`, else the canvas), up to 16 frames on a contact sheet — the cells
scaled down to `max_width` (default 2048), never the 8 px gaps or the 24 px
label strips, a failing frame drawn as its error card — written through
`FrameWriter` as a PNG, with one sentence per frame that failed or warned
before "Written to <path>."; `format: "svg"` answers one frame's SVG, its
diagnostics and its ctx, and refuses a non-null `path`, `background` or
`max_width` by name — the png sheet's, and svg writes no file (spec §11 G-19
(a)). A frame at or past `durationInFrames` is drawn, not refused, with
`progress` clamped at 1, since a clip longer than its length draws those
frames too (G-9, G-19 (b)). A png sheet draws at most 134,217,728 px of
frames (frames × width × height, two at 8192²), and a call past that is
refused before any frame is drawn or any file written (G-20 (d)).
`import_graphic_font {path}` copies a
`.ttf`/`.otf` into `graphics/fonts/` through the store (G-14), rescans, and answers
`families` — the family names the ENGINE reads from that file, from a
throwaway library holding it alone, because CoreText names some files
differently — and `library_families`; a file that loads no face is refused
in the engine's words. `import_graphic_asset {path, name?}` copies a PNG,
JPEG, GIF, WebP, SVG or SVGZ into `graphics/assets/` and refuses anything
else and an empty file; a name `asset(name)` cannot use is filed under a
legal one, `name` answering the name used and `renamed_from` the name asked
for, and a renamed copy never replaces (spec §11 G-23). Both are not
undoable and never dirty the document.

Issue batch B84 (#103) adds three, and the kept texts they work over (spec
§11 G-27, G-28, G-29). The store keeps the last 10 texts of each module in
`graphics/history/` whenever it sees a module's text replaced while the
project is open, and when a module is deleted; `kept` — `[revision]`, newest
first — is in the answers of `write_graphic`, `get_graphic {name}` and the
three tools, and `get_graphic {}` answers `history: [{name, kept}]`, deleted
modules included. `write_graphic`'s `note` is "not undoable; the text it
replaced is kept (the last 10 per module) — restore_graphic brings it back".
`delete_graphic {name}` answers `{ok, name, revision, kept, note}`; it is
refused while a clip draws the module, in a sentence naming the clips per
container ("… is still drawn by clips 4 and 9 on the timeline and clip 12 in
nest 7; …"), keeps the deleted text, and leaves fonts and assets alone.
`rename_graphic {name, to}` answers `{ok, name, renamed_from, clips,
revision, kept, note}`: the file, its kept texts and every clip that names
it move — the clips by one `set_graphic {name}` per container with no
schema, as ONE undo step "Rename Graphic" — and Undo renames the file back
(the document repairs a journalled rename after every committed change,
never onto a deleted name). It refuses an absent module, a `to` that is not
a module name, a `to` whose file exists (`graphics/<to>.js already exists`),
a `to` a clip already names with no file behind it, and an open nest, in
that order. `restore_graphic {name, revision?}` writes a kept text back —
the newest, or the one named — and answers the compile as `write_graphic`
does, with `restored` and `kept`; it keeps the text it replaced, and it
works for a deleted module. None of the three takes `scope`; the file acts
are not undoable and never dirty the document (G-3). Their menu items —
File ▸ Rename Graphic…, Delete Graphic…, Restore Graphic Version… (§9,
§11 G-30) — each put up one small sheet and run the same three bodies
(`ProjectDocument+GraphicFiles.swift`).

**An action's graphic props** (§11 G-34). `set_action_end`'s handler fills
`schema` itself: when the patch names `graphic` and the action's clip —
looked up in the call's scope, so a clip in a nest is found there — is a
graphic clip, it sends the CURRENT revision's schema of the module that clip
is drawn by, read as `set_graphic`'s is; otherwise it sends none. The core
then answers every case in its own sentence: `clip N is not a graphic clip`
for any other clip, asked before the schema, and `graphic.props.<key> needs
its module's schema to animate, and none came with the op` for a value whose
module is missing or does not compile, while a `null` prop still removes. A
caller's own `schema` is refused by the argument gate as a stranger.

G5b gives the person the same doors (§9): File ▸ Add Font to Graphics… and
Add Image to Graphics… run the two imports' own body
(`GraphicStore.importFont` / `importAsset`), Help ▸ Graphics Reference opens
the file `graphic_reference` answers, and **Insert ▸ Graphic…'s Insert is
`write_graphic` of a template (or, from its From File…, a chosen `.js`)
then `add_graphic_clip`** — one undo step, "Insert Graphic", placed by Add
Text's rule (§11 G-16) — or, for a graphic listed under This Project, the
clip alone with no copy (§11 G-45). Its two acts are the agent's too:
**`list_graphics {}`** answers `categories [{name, graphics: [{name, title,
description, category, from, ok}]}]` in the sheet's order (This Project
first when the package holds a module, then the templates' `meta.category`
groups by name, Other last; a This Project title another one shares is
"<title> — <name>"), and **`insert_graphic {name, from}`** (`from` is
`template` or `project`) places the clip as the sheet's Insert does,
answering `editResult`'s reply with `name`, the module placed; an unknown
name is refused naming it and listing that origin's names, a module that
does not compile with "graphics/<name>.js does not compile: …".
**`export_graphic {name, from, path}`** (§11 G-46) is the sheet's Export…:
the graphic resolved and refused as `insert_graphic` resolves it, its job
built on main (a fresh library of the bundled faces, then the project's
fonts and assets; a template's of the bundled faces alone), and the package
written off main on the server thread (`offMainTools`, like
`render_graphic`; no `scope`). It draws every frame up to 900 (else 900
evenly spaced) with the default props, then each `enum` option and boolean
opposite (at most 32, over 30 frames each), and packs the project font blobs
and image assets the engine's `usage()` reports (`rc_graphic_library_usage`),
never a bundled face; the core writes the stored zip
(`rc_graphic_package_write`) to `.<file>.partial` beside the destination,
which is renamed over it. The path goes through `nonEmptyOutputPath`,
`destinationURL(_, extension: "fjgraphic")` and `requireFolder`; the reply is
`{path, files: ["manifest.json", …], frames, failed_frames}`; a refusal writes
nothing. It is ask-first in the assistant (§7.9b).
**`import_graphic {path}`** (§11 G-47) is the Import Graphic sheet's Import,
without the sheet: the doors a person uses are a `.fjgraphic` opened from the
Finder (`ProjectDocumentController` hands it to
`GraphicImportSheetController.open(packageAt:)`, which waits for launch and
restoration, then picks the front project or makes an untitled one) and the
browser's From File…, which takes a `.js` or a `.fjgraphic`. The package is
read and checked by the core (`rc_graphic_package_read`), then by the app
(each font loads, each asset's name is one `asset(name)` can use), every
refusal "<file name> cannot be imported: <sentence>"; then planned and
copied (`GraphicPackageImport.swift`) under the manifest's names — a file
already there with the same bytes reused, a module or font name taken by
something else suffixed `-2`, `-3`, …, a picture name taken by a different
picture refused — fonts, then assets, then the module, none replacing a
file, a failure removing what it wrote, one rescan. It runs on main, has no
`scope`, and is not ask-first: it writes only inside `graphics/`. The reply
is `{name, renamed_from?, title, module: written|reused, fonts: [{name,
renamed_from?, action}], assets: [{name, action}], note}`.

**Dev tools** (§11 V-1..V-3, road map 11). A tool compiled only under
`FRAMEJOB_DEV_TOOLS` — set for Debug and Release, never for Distribution, so
`make dist`'s binary holds none of their code (`dist_check.py`). A dev tool
is an ORDINARY tool: a handler and a catalog row from
`AgentServer+DevTools.swift`, spliced in before the file tools, covered by
the parity check and the argument gate like any other, and counted apart
from the one hundred and four product tools (`tools/proof/dev_tools.py`).
**`snapshot_ui {window?, view?, appearance?, path?, fill_preview?, layout?}`**
is the first. With no `window` it lists the visible windows (kind, class,
title, frame, content size, scale, occluded, key, main, the editor's project,
any attached sheet). With `window` — `editor`, `sheet`, `settings`,
`welcome` or `recorder` (the New Recording panel, found open and never built by
the call) — it captures through `cacheDisplay` (V-3), which needs neither an
active app nor a visible window, as an image block plus a JSON text block
and a PNG on disk; `view` narrows the editor to `toolbar`, `preview`,
`inspector` or `timeline`; `appearance` is REFUSED whatever its value,
naming the launch-time way (road map 11's V3: a live switch left the colours a
view took when it was built in the launch appearance, so the picture was a mix
the app never draws) — the look is the instance's, set at launch by the
dev-only default `-RCDevAppearance light|dark`, which puts `NSApp.appearance`
before any window is built, and every capture answers the `appearance` it drew
in; its scale is the window's `backingScaleFactor` unless the instance was
launched with the dev-only default `-RCDevCaptureScale 1|2|3` (§11 #539), which
draws every capture at that many pixels per point whatever screen its window is
on (any other value is ignored, with one stderr line) — the answer's `scale` and
the dump's are the capture's, `window_facts.scale` stays the window's
(a second dev-only default, `-RCDevLookGalleryDump <folder>`, has the Look
gallery write each completed generation of thumbnails to
`<folder>/<N>/<tile>.png` — `none`, the kind, or `lut-<media id>` for an imported
LUT's tile (§11 GR-8) — then `<folder>/<N>/manifest.json`
`{generation, t, clips, missing, tiles}`, last, `tiles` the tile names in the
gallery's order; §11 GR-7); `fill_preview` (default true) puts `render_frame`'s picture at the
playhead under the canvas overlay for the capture and takes it out after;
`layout` (default true) writes `<name>.layout.json` beside the PNG — every
view's class, identifier, frame in capture points, hidden, ambiguity,
intrinsic size, label text (a text view's text, never a field editor's and
never a secure field's) and tooltip (never a secure field's), and after a
view that names parts in place of subviews (the Assistant tab's transcript,
whose entries are ranges of one text view, AI-17) one record per part, its
id, text and rect — and answers its
`problems` (ambiguous layout, a view whose alignment rect passes its
superview's bounds, a truncated text field), AppKit's private `_NS…` views
counted apart. It runs on the server thread; a file-panel sheet is refused,
since it would capture as one colour.
**`perform_menu_item {path?}`** runs a main-menu item by its titles, e.g.
`["File", "Export…"]`, as the menu shows them (a validator may retitle one:
Undo reads "Undo Add Marker"; Clip ▸ Look ▸'s LUT items are filled for the
named window's project before each level is read, as AppKit fills them before
it shows the menu, §11 GR-8). It is delivered to the NAMED project's editor
window's own responder chain — the first object from its first responder
down, then the window, its delegate, controller and document, then the app,
its delegate and the document controller, that answers the action — never
nil-targeted, so it works with the app inactive and the window covered
(road map 11's V2b, measured). With no `project` it is the frontmost
project's window, or the app's chain alone when none is open; app-level
items (Settings…) resolve at the chain's tail. The action's undo is one
explicit group on the window's document, opened at the item's first undo
registration: an edit it makes is one undo step, and an item that edits
nothing leaves undo and redo as they were. It answers after a settle: the
attached sheet, the app-modal window and the visible windows read every 20 ms
until five reads agree, bounded at 3 s — so a sheet that arrives a turn later
is in the answer — with the target, `perform_ms`, `sheet_at_return` (whether
a sheet was attached when the action returned), `settle_ms`, the sheet, the
windows opened and closed, the modal window, `active` and the window's facts.
Refused by name and running nothing: an app-modal window already up, an empty
path, a title not found (the level's titles listed), a submenu, an item with
no action, a selector the allow-table (`UIMenuTable.swift`, a mirror of
`tools/proof/capture_spike/inventory.json`) reads `framework` or `modal` or
does not list (`unclassified`), an item whose own target does not answer its
action (disabled, as AppKit shows it), an action nothing in the chain
answers, and an item its own validator disables. With no `path` it lists
every leaf: path, selector, verdict, refusal, enabled, state, hidden.
**`cancel_sheet {}`** closes the sheet attached to a project's window the way
its own Cancel would — a file panel is ended with `.cancel`, any other
sheet's Escape button pressed, or its only button — and refuses anything
else, naming the buttons; a file panel with no parent window is refused in
its own words. It answers after the same settle.
**`select_inspector_tab {tab?, sub_tab?, section?}`** (road map 11's V3) picks the
inspector's tab — `clip`, `media`, `document` or `assistant` — and, with `tab: clip`, the
Clip tab's sub-tab — `text`, `shape`, `graphic`, `picture`, `sound` or `clip` —
in a project's editor window, through the calls the two strips' clicks make
(`InspectorViewController.select(_:)`, `selectClipSubTab(_:)`), so what
`snapshot_ui` captures is what a click shows; the pick is forgotten when the
selection changes, as a click's is. With no `tab` it changes nothing. It
answers `tab`, and on the Clip tab with a selection the active `sub_tab` and
the `sub_tabs` on offer (else `null` and `[]`). Refused, leaving the inspector
as it was: a value outside either list, a `sub_tab` without `tab: clip`, a
`sub_tab` with no clip selected, a project with no editor window, and a
`sub_tab` the selection does not have (the refusal lists the ones it has).
`section` (grading GR5b), with or without `tab`, then scrolls the
shown pane so that section's top is the visible top (clamped to the pane),
writing no preference and opening nothing; a section the shown pane does not
hold is refused, naming the ids it holds ("The shown pane has no section <id>;
its sections are a, b, …"), with the tab and sub-tab it showed put back. The
answer carries `"look_thumbnails_pending": true` only while a Look gallery in
the shown pane is open and owes renders (§11 GR-7), so a capture can wait for
its thumbnails.
**`assistant_send {text, timeout?, pane?, stop_after?}`** and **`assistant_answer
{answer, timeout?, pane?, stop_after?}`** (road map 12 A1) drive a project window's assistant session
(§7.9b): `assistant_send` types `text` into it, opening the session on the
first call, and `assistant_answer` answers the ask-first question it stopped
on — `allow` or `deny` — or `stop`s the turn. Both wait, releasing the
lane's lock (`AgentLane.releasingLock`, since the turn's own calls need it),
until the turn is no longer busy or `timeout` seconds pass (default 120,
1…600), and answer `state` (`finished`, `asking`, `closed`, or `running`
past the timeout), the pending `question` (tool, path, exists, sentence) or
`null`, the streamed `text`, every event since the call but the text and
progress deltas, and `waited_ms` — never the key or the model. With
`stop_after` (seconds, 0.1…600 and less than `timeout`; on `assistant_answer`
only with `allow`; issue batch B15) the wait presses Stop once, through the
tab's own forward `editor.assistantStop()`, when that many seconds have
passed with the turn still busy or asking, and `stopped_ms` answers when (else
`null`). Refused by
name, changing nothing: a project with no editor window, a send while a
turn runs, allow or deny with no question pending, stop with no turn
running, an answer to a window with no conversation, an `answer` outside
the three, a `timeout` outside 1…600, a `stop_after` outside its range or
with an answer other than `allow`, an empty `text`, and a session that
cannot open (its own sentence). Both run on the server thread. A turn in a
launch WITHOUT the server is the dev-only launch default
`-RCDevAssistantSend <text> -RCDevAssistantReport <path>` (both from the
argument domain): after launch it opens an untitled project, sends `text`,
waits up to 120 s, reads `get_project` through the lane pinned to that
project, writes one JSON report (`ok`, `error`, `server_running`, `state`,
`text`, `events`, `get_project`) and closes the session.
The dev-only launch default `-RCDevAssistantAutoCompact <tokens>` (argument
domain, spec §11 AI-18) replaces the person's end-of-turn compaction
threshold (300 000 unless changed in Settings, §11 AI-20) for the launch,
even with compaction turned off, so a proof can compact a short
conversation (`assistant_compaction_proof.py` launches with 1).
The dev-only launch default `-RCDevGraphicImportAccept YES` (argument domain,
§11 G-47) makes the Import Graphic sheet press its own Import once it is up,
so `graphic_import_proof.py` can see a package opened at launch land.
With **`pane: true`** (road map 12 A2) both go through the Assistant tab's own
controls instead: `assistant_send` sets the composer (ending any edit) and
clicks Send, refused if the composer still holds the text after;
`assistant_answer` calls Allow's or Deny's own `mouseDown` with a left click
at its centre, or clicks Send while it reads Stop. The order is the target,
then (with `pane`) the control in a window and not hidden — else refused by
name, `… select_inspector_tab {tab: "assistant"} first`, opening and changing
nothing — then the session and the refusals above.
**`play_preview {seconds, rate?, digests?, seek_to?, stale_ticks?, stale_armed?}`** (issue #127, §11
G-36) plays a project's preview forward and measures it. It pauses, waits up
to 5 s for a seek to land, notes the playhead (`from`), sets the transport's
rate — `rate` 1, 2 or 4, default 1 — through `Playback.setRate`, and sleeps
`seconds` (0.5…60) on the server thread; with `seek_to` (ticks, snapped to the
frame grid) it sleeps half, notes the playhead (`seek_from`), seeks through
the asked door (`Playback.seek(to:)`, as a click on the ruler does) and sleeps
the rest. `stale_ticks` (a non-empty list of ticks ≥ 0, issue #329) hands the
seek's prefetch session requests it must not follow, through
`GraphicPrefetch.reach`, the compositor's own call: in the seek's own main
hop, where the session is already installed and not yet armed, or, with
`stale_armed: true`, once a frame in the seek's first `armFrames` (4) frames
was composed (so its request armed the session), polled every 10 ms for at
most min(2 s, `seconds` / 2) from the seek; the second half still ends
`seconds` / 2 after the seek, the wait included. Then it notes `to` and
pauses. While it plays,
`PlaybackTrial.swift` records each frame the compositor finished on the
document's key: its time, its compose time, and, with `digests: true`, the
SHA-256 of the destination buffer's rows (each row's first `width × 8`
bytes, 64RGBAHalf). It answers, keys in this order: `from`, `to`, `rate`,
`wall_seconds`, `frame_ticks` (f, the built composition's frame duration),
`frames_expected` (max(0, k1 − k0 + 1), k0 = ⌊from / f⌋ — ⌊seek_to / f⌋ with
`seek_to` — and k1 = ⌊(to − 1) / f⌋), `frames_composed` (the distinct ⌊t / f⌋
in [k0, k1] among the frames served), `composed_ratio` (3 places; 0 when none
were expected), `compose_ms {mean, p95, worst}` (nearest rank, over every
frame served), `seek_from` (only with `seek_to`), `stale_reached` (only with
`stale_ticks`: the ticks reported — all of them, or `[]` when the armed wait
ran out) and `digests` (only when asked: a tick string → SHA-256 hex).
Refused, each in its own sentence and before anything moves: `stale_ticks`
without `seek_to`, an empty `stale_ticks`, a negative tick, and
`stale_armed` without `stale_ticks`. Refused, each in its own sentence: a
project with no editor window and a preview with no item to play, changing
nothing, and a preview still seeking after 5 s, which it has paused. It ends
paused where the play reached. It is
`playback_prefetch_proof.py`'s instrument.
**`graphic_memory {pressure?}`** (issue #127, §11 G-37) answers the graphic
rasters' one memory budget and the frames a document keeps. It needs no
project and runs off the main thread. `pressure` — `"normal"`, `"warning"` or
`"critical"`, any other value refused in its own sentence before anything
moves — first sets a SIMULATED memory-pressure level, which holds against the
system's real events until the tool sets `"normal"`; that clears the
simulation and applies the last real level. It answers `physical_bytes`
(`ProcessInfo.physicalMemory`), `budget_bytes` (a quarter of it at normal, an
eighth at warning, 0 at critical), `pressure` (the level in force),
`held_bytes` (every session's rasters held ahead now), `held_peak_bytes` and
`held_peak_entries` (the highest totals since the last answer, which resets
them to the current ones), `kept_bytes` and `kept_frames` (the kept frames'
total and count, over every document), `kept_hits` (how many compositor
requests the kept frames have answered since launch), `ahead_bytes` (the kept
frames a background pass drew ahead that the compositor has not passed, §11
G-38), `ahead_evicted` (those a trim pushed out while still ahead, since the
last answer, which resets it to 0), `pass_activity` (whether a running
background pass holds the App Nap opt-out), `image_cache_bytes` (what the
engine's decoded-image cache of PNG and JPEG assets holds, §11 G-39) and
`image_cache_limit` (its limit: `budget_bytes / 16`, 0 under
`FrameJobGraphicImageCacheOff`). It is `graphic_memory_proof.py`'s,
`background_render_proof.py`'s and `image_cache_proof.py`'s instrument.

**`loudness_meter {reset?}`** (road map "audio" AP7, §11 AU-77) answers the
live loudness meter of a project's editor window — the true mix as the
preview plays it at ×1, rebuilt from the taps (AU-70) — on the main thread;
a project with no editor window is refused in its own sentence. `reset: true`
first resets the meter as the column's Reset does (reason `manual`). It
answers `measuring` (frames summed within the last 0.15 s), `rate` (the
transport's), `momentary_lufs`, `short_term_lufs`, `integrated_lufs`,
`true_peak_dbtp` (null where there is none, `"-inf"` for digital silence),
`from_frame` and `to_frame` (the frames measured since the reset, `[from,
to)`, at `sample_rate`, the taps' rate; null before any), `resets` and
`last_reset` (`manual`, `jump` or `overrun`). It mirrors no edit — View ▸
Loudness Meter and Reset are view state — and is `audio_ap7_proof.py`'s
instrument, read beside `play_preview`.

**`playback_rebuilds {reset?}`** (road map "creator-jobs" SW0, §11 SW-1)
answers a project's editor window's preview rebuilds, on the main thread; a
project with no editor window is refused in `loudness_meter`'s sentence shape.
A rebuild is what a structural edit (one that changes the plan JSON or the
audio DSP) costs: a new player item built off the main thread, then swapped in
with a restore seek. `PlaybackRebuildLog` notes a generation's start in
`Playback.startRebuild`, keeps its entry at `finishRebuild`'s success arm,
after the generation guard (a superseded or failed build is never an entry),
and fills the entry's landing at the first seek landing after it
(`seekFinished()`). `reset: true` first empties the list and the count. It
answers `{count, rebuilding, rebuilds}` in that key order: `count` (entries
since the last reset; the list keeps the last 256), `rebuilding` (a rebuild in
flight) and `rebuilds`, oldest first, each `{generation, built_ms,
landed_ms}` — ms from the start to the build and to the landing, rounded to
0.1, `landed_ms` null until it lands. The dev-only launch default
`-RCDevRebuildHold <s>` (SW-4) delays each rebuild's main-thread landing by s
seconds through `Playback.rebuildHop`, installed only when it is given. It
mirrors no edit, and is `rebuild_log_proof.py`'s and SW-S2's
(`creator_spike/angles_spike.py`) instrument.

**`land_recording {voice, movie?, door?, enhance?, place?, follow_wait?, cursor?, cursor_mode?,
