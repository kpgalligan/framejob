# 5.2a Project — the JSON schema (format version 27): the document, canvas, media, a clip's source and video

Audio, text, shape, `actions[].end`, `transition_in`, a clip's name and label, tracks, nests and ids are §5.2b.

The Rust value, serialized by serde. Small, no pixels. All times are
ticks, all positions canvas pixels, colors `[r, g, b, a]` floats 0–1 — FOUR
numbers, never a three-element form and never clamped, with
`video.chroma.key` the one `[r, g, b]` in the schema — angles degrees,
opacity/volume 0–1 (volume may exceed 1, up to 4).

**What a PATCH against this schema means**, once for every op that takes one
(§6's five `set_*`, `add_text_clip`'s `text`, `add_shape_clip`'s `shape` and
an action's `end`): it **merges key by key at every depth** — a nested object
merges into the stored one rather than replacing it, so `{"shadow":
{"blur": 40}}` keeps the colour and the offset — a key set to **`null`
clears** that key (in an action's `end`, where the patch IS the stored
value, it removes the key, which is the same act one level up), and an
**array replaces** its whole list. A key or a value the vocabulary does not
have is refused by its dotted path, array indices included, and never
dropped or corrected (§6, `core/src/patch.rs`,
`CONTEXT.md`'s **Patch**). The FILE reader is the lenient one and stays so:
it opens what a newer build wrote (§5.6).

```json
{
  "version": 8,
  "canvas": { "width": 1920, "height": 1080, "fps": [30, 1],
              "background": [0, 0, 0, 1], "fit_new_clips": true,
              "timecode_frames": true },
  "media": [
    { "id": 1, "path": "/Users/…/talk.mov", "bookmark": "<base64 or null>",
      "kind": "video", "duration": 36000000, "width": 1920, "height": 1080,
      "fps": [30000, 1001], "has_video": true, "has_audio": true,
      "has_alpha": false, "original": null }
  ],
  "tracks": [
    { "id": 1, "name": "Track 1", "hidden": false, "muted": false, "locked": false,
      "solo": false }
  ],
  "clips": [
    { "id": 17, "track": 1, "start": 0, "duration": 12000000,
      "source": { "kind": "media", "media": 1, "in": 3000000, "reversed": false },
      "enabled": { "video": true, "audio": true },
      "speed": 1.0,
      "video": { "x": 0, "y": 0, "scale": 1.0, "rotation": 0, "opacity": 1,
                 "crop": { "l": 0, "t": 0, "r": 0, "b": 0 },
                 "corner_radius": 0,
                 "shadow": null,
                 "color": { "brightness": 0, "contrast": 0, "saturation": 0, "hue": 0 },
                 "chroma": null,
                 "filters": [], "reflection": null, "spotlight": null,
                 "obscure": [], "blend": "normal", "motion": null },
      "audio": { "volume": 1.0, "muted": false, "fade_in": 0, "fade_out": 0,
                 "duck": null, "mono": false, "keep_pitch": true,
                 "pan": 0, "compressor": null, "noise_reduction": 0 },
      "text": null, "shape": null, "graphic": null,
      "actions": [
        { "id": 1, "start": 2400000, "duration": 900000, "curve": "ease_in_out",
          "end": { "video": { "scale": 0.6, "x": 520 } } }
      ],
      "transition_in": null,
      "name": null, "label": null }
  ],
  "markers": [ { "id": 1, "time": 6000000, "name": "Intro", "color": "red", "chapter": true } ],
  "next_id": 18,
  "nests": []
}
```

- `source.kind` is one of `media` (video/audio file, with `in` = source
  time of the clip's first frame and `reversed` = play it back to front),
  `still` (`media`, `at` — a freeze frame), `image` (`media` — a
  PNG/JPEG/HEIC), `text`, `shape`, `graphic` (format version 10, road map
  10 — described by the clip's `graphic` key), `nest` (`project` — the ID
  of an entry in the project's `nests[]`, M3), `adjustment` (no other key,
  format 15, spec §11 GR-6 — no picture: its
  `video.color`, point filters and `opacity` grade what is drawn behind it;
  never inside a nest). `speed` applies to `media`
  only; `still`, `image`, `text`, `shape`, `graphic`, `nest` and
  `adjustment` have no source bound and any duration.
- `canvas.output` (format version 23, §11 HD-2, HD-13): the project's dynamic
  range, `"sdr"` (Rec. 709, every project before format 23) or `"hlg"` (every
  frame composed in HLG-encoded BT.2020, §7.5), written last in `canvas` and
  only when `hlg`, so an SDR project's file is the text it was; absent reads
  `sdr`. A nest composes in its document's output. Set by `set_canvas
  {output}` (§6) and the Document tab's Dynamic Range popup (§4.3).
- `canvas.blending` (format version 24, §11 GR-18, HD-9, HD-16): how layers
  blend, `"encoded"` (every project before format 24, §11 GR-3) or
  `"linear"` (every layer decoded to the project's own transfer as scene
  light after its grade, blended there and encoded once by the output pass,
  §7.5), written after `output` and only when `linear`, so every other
  project's file is the text it was; absent reads `encoded`. A nest blends as
  its document does. Set by `set_canvas {blending}` (§6) and the Document
  tab's Blending popup (§4.3).
- `media[].original` (format version 11, §11 #228-O): `null`, or
  `{ "path": "/Users/…/talk.webm", "bookmark": "<base64 or null>" }` — the
  WebM or Matroska file the built-in copy made this media's `.mov` from.
  `path` and `bookmark` above stay the COPY's, which is what plays, caches
  and consolidates; the original is what the media is named after, what
  Reveal in Finder opens, and what a copy that is gone is copied again from
  on open (§7.7). A blank `path` is an error and a blank `bookmark` is
  stored as `null`; a relink's probe replaces it, so a relink to any other
  file clears it. Last in the media object but `color`.
- `media[].color` (format version 19, §11 GR-16): absent, or a VIDEO media's
  Camera Log — `{ "log": "slog3", "gamut": "s_gamut3_cine" }` (a maker's log
  curve, `apple_log` with `bt2020`, `apple_log2` with `apple_wide_gamut`,
  `slog3` with `s_gamut3_cine` or `s_gamut3`, `vlog` with `v_gamut`, and —
  format version 25, §11 HD-17 — `canon_log2` and `canon_log3` each with
  `cinema_gamut` or `bt2020`, the first the default), or
  `{ "lut": 12 }` (a `lut` media used as the input conversion instead), with
  `"detected": true` when import read it from the file's label (Apple Log and
  Apple Log 2), and — format version 22, §11 HD-12 — `"pq": {"file": 4000,
  "from": "max_cll", "peak": 1000}` on a PQ file: `file` the peak import read
  from its HDR10 metadata in whole cd/m² (the sample description's, else the
  first sample's SEI; MaxCLL when non-zero, else the mastering display's
  maximum), `from` which field (`max_cll` or `mastering_display`, present
  exactly when `file` is), `peak` the person's override (1–10000), each
  written only when set and `{}` when import read nothing; `pq` is written
  after `detected`, and a colour may hold `pq` with neither `log` nor `lut`.
  Format version 26, §11 HD-20 (b): an IMAGE media whose decoded space is
  PQ-based carries `pq` too, read from its PNG `cLLI`/`mDCV` or its HEIF or
  AVIF primary item's `clli`/`mdcv`, and an image's colour is that `pq` alone.
  Each key is written only when set, and the key itself only when the media
  has one, so a project with none writes the text it did before version 19
  (and one with no PQ file the text it did before 22). Every clip of the media, and its reverse, is converted
  with it at step 0 (§7.5), before the chroma key and every grade; Show
  Ungraded keeps it. `set_media_color` sets it (§6); a file naming a pairing
  the curve does not take, a `lut` that is no `lut` media, or a setting on an
  audio or LUT media, or on an image beyond a PQ still's `pq`, is refused on open in `set_media_color`'s
  sentence, as is a `pq` peak outside 1–10000 (`color.pq.file must be
  1–10000 cd/m², not 0`) or a `from` without a `file` (`color.pq.from goes
  with color.pq.file`). Last in the media object.
- `graphic` (format version 10, road map 10's G2a; §11 G-3, G-4, G-12):
  `null` for every clip but a `graphic` one, whose description it is —
  `{ "name": "lower-third", "width": 1920, "height": 1080, "in": 0,
  "length": null, "props": { "title": "Kevin", "accent": "#2d7ff9" } }`.
  `name` is the module `graphics/<name>.js` in the package, matching
  `^[a-z0-9][a-z0-9-]{0,62}$` (a file whose name breaks it is refused by
  `validate`); `width` and `height` the size it draws at, 1–8192 — its
  source size; `in` the graphic's own time at the clip's first frame, owned
  by the trims and `split`; `length` the graphic's own length, `null` for
  "ends with the clip" (`in` + the clip's duration, G-9·c); `props` the values it is drawn with, at most 64, in
  the caller's key order (written back byte for byte), a `color` one as
  lowercase `#rrggbb` or `#rrggbbaa`. Every key defaults; an absent
  `graphic` on a graphic clip is tolerated as an absent `text` is.
- `actions[].end.graphic` (format version 13, §11 G-34): a graphic clip's
  props as an action's targets — `"end": {"graphic": {"props": {"size":
  129}, "kinds": {"size": "number"}}}`, `props` before `kinds`. `kinds` is
  each prop's schema type, written by `set_action_end`; a `kinds` in a
  patch is discarded. An end is stored as found, so there is no migration
  step.
- `actions[].end.speed` (format version 27, §11 SR-10): a MEDIA clip's rate
  as an action's target — `"end": {"speed": 2.0}`, a number beside the
  groups, stored clamped to ×0.1–×1000 by `set_action_end`. The clip ramps
  from the rate in force to it along the action's curve and holds it after
  (§5.4); its `start` and `duration` never move, its out point is
  `in + S(duration)`. On any other source, or as any other JSON kind, it is
  ignored (the op refuses it). Its default is none, so there is no migration
  step.
- `source.reversed` (M3) is a fact, not an instruction: the core does no
  pixel work, so it changes neither the plan nor the recipe, and Swift
  substitutes a pre-rendered reversed asset for that media's segments
  (§11). `in` is then measured in the reversed stream, which is the same
  length — so an `in` of 0 is the media's last frame, and every time
  computation in the core is unchanged.
- `enabled.video` / `enabled.audio` — Detach Audio flips them across two
  clips (§6). A media clip with `has_audio` false has `audio: null`.
- `video.shadow`: `{ "color": [...], "opacity": 0.5, "blur": 12, "angle": 315, "distance": 8 }`.
- `video.color`: `{ "brightness", "contrast", "saturation", "hue" }`, offsets
  from neutral, any finite value; `hue` is degrees of HSV-hue turn keeping
  Rec. 709 luma (§11 GR-33), taken modulo 360. In format 15 (§11 GR-2) nine tone keys
  follow `hue`, in this order: `exposure` (−3…+3, in EV), `temperature`,
  `tint`, `highlights`, `shadows`, `whites`, `blacks`, `vibrance` (each
  −1…+1) and `fade` (0…1). Each defaults to 0 and is **written only when not
  0**, so an untoned project's text is what it was; out of
  range is refused by its dotted path (`video.color.exposure must be between
  -3 and 3, not 3.5`); an action interpolates each like any number. A file
  numbered 1015 (the grading branch's builds, §11 GR-9) is read as version 15.
- `video.wheels` (format 16, §11 GR-11): absent, or `{ "lift", "gamma",
  "gain" }`, each `{ "x", "y", "master" }` — `x, y` the colour push (its angle
  the hue on the HSV ramp, 0° red; its length the strength) and `master` the
  brightness, each −1…1 and the push inside the unit circle (`x² + y² ≤ 1`,
  to 1e-9, so a rim point is never refused). Every key is **written only when
  not 0**, a neutral wheel not at all and a neutral `wheels` not at all, in
  the order lift, gamma, gain and x, y, master, before `look`; out of range is
  refused by its dotted path (`video.wheels.lift.x must be between -1 and 1,
  not 1.5`, `video.wheels.lift must lie inside the unit circle (x² + y² ≤ 1),
  not x 0.9, y 0.6`), never clamped. An action interpolates each number; its
  end is clamped (NaN to 0, each value to ±1, a push past the rim divided by
  its `hypot`). A file numbered 1–15 (or 1015) opens and is stamped 16.
- `video.curves` (format 17, §11 GR-12): absent, or `{ "master", "red",
  "green", "blue" }`, each a list of 2–16 points `[x, y]`, x strictly rising,
  x and y 0…1 (both bounds inclusive). A channel equal to the **identity**
  (first x 0, last x 1, every y = x) is not written, and `curves` not at all
  when all four are, in the order master, red, green, blue, after `wheels`
  and before `look`; `set_video` stores an identity channel as none, so an
  identity patch on an uncurved clip is an identity. A list replaces a
  channel whole and `null` removes it. Out of range is refused by its dotted
  path (`video.curves.red needs 2 to 16 points, not 17`,
  `video.curves.red[2].x must be between 0 and 1, not 1.2`,
  `video.curves.master[2].x (0.4) must be greater than
  video.curves.master[1].x (0.5)`), never clamped. An action interpolates the
  points (§5.4); its end is clamped (x and y to 0…1, a channel with a NaN, a
  count outside 2–16 or x not rising removed, an identity removed). A file
  numbered 1–16 (or 1015) opens and is stamped 17.
  Format 20 (§11 GR-32) adds the hue curves after `blue`: `"hue_hue"` (Hue
  vs Hue) and `"hue_sat"` (Hue vs Sat), each a list of 2–16 points `[hue,
  value]`, hue in degrees, 0 ≤ hue < 360, strictly rising; hue_hue's value a
  shift in degrees −180…180 (0 none), hue_sat's a gain 0…2 (1 none). A hue
  curve whose every value is its neutral, whatever its x's, is the identity:
  not written, and stored as none by `set_video`. Refused by its dotted path
  (`video.curves.hue_hue[2].x must be at least 0 and below 360, not 360`,
  `video.curves.hue_hue[1].y must be between -180 and 180, not 200`,
  `video.curves.hue_sat[0].y must be between 0 and 2, not 2.5`, and the count
  and rising sentences above), never clamped; an action's end is clamped (x
  to 0…360, then a last x of 360 or x not rising removes the channel, values
  to their range). A file numbered 1–19 (or 1015) opens and is stamped 20.
- `video.qualifier` (format 18, §11 GR-13): absent, or `{ "hue": { "center",
  "width", "softness" }, "saturation": { "low", "high", "softness" }, "luma": {
  "low", "high", "softness" }, "invert": true }`, after `curves` and before
  `look`. A range is absent when off and `invert` written only when true, so
  the key is absent when no range is on and Invert is off. Hue is in degrees:
  `center` 0–360 (wrapping; 360 is 0), `width` 0–360 (the fully selected band
  about the centre), `softness` 0–180 (the fall-off outside each edge);
  saturation (HSV, C / max) and luma (Y′: Rec. 709, BT.2020 in HLG) are 0–1 with `low ≤ high`
  and `softness` 0–1. `{}` turns a range on at its default (hue {30, 50, 25},
  the levels {0, 1, 0.1}), a partial range merges and `null` turns it off.
  Out of range is refused in `in_range`'s sentence
  (`video.qualifier.hue.center must be between 0 and 360, not 400`) and
  the order in its own (`video.qualifier.saturation.low (0.8) must not be
  greater than video.qualifier.saturation.high (0.2)`), never clamped. ONLY
  an adjustment clip takes one: on any other clip a non-neutral qualifier is
  an error (`clip 7 is not an adjustment clip and cannot take a qualifier`),
  and one that arrives through a file or an action's end is inert (the recipe
  publishes it only in an adjustment source, §7.3). An action interpolates its
  numbers, the hue centre the short way round (§5.4); its end is clamped (a
  NaN removes its range, numbers to their bounds, the centre `rem_euclid 360`,
  `low > high` closed at `high = low`). A file numbered 1–17 (or 1015) opens
  and is stamped 18.
  Format 21 (§11 GR-35) adds `"blur"` after `invert`: the cleanup blur, 0–1
  (0 off, written only when above 0), a Gaussian of the selection with σ =
  24·blur canvas pixels (§7.5). Neutral is no range, not inverted and blur 0,
  so a blur alone is kept and saved (and refused on another clip) but draws
  nothing. Refused outside 0–1 in `in_range`'s sentence, checked after luma
  (`video.qualifier.blur must be between 0 and 1, not 1.5`), never clamped; an
  action's end is clamped (non-finite to 0, then 0–1). A file numbered 1–20
  (or 1015) opens and is stamped 21.
- `video.chroma` (M3): `{ "key": [r,g,b], "tolerance": 0.2, "softness": 0.1, "spill": 0.5 }`.
- `video.filters` (M3): an ordered list of `{ "kind": …, "amount": 0..1 }`,
  at most **four** — a shader budget, not taste: the uniform block carries
  four (kind, amount) pairs. `kind` ∈ `blur`, `sharpen`, `pixelate`,
  `sepia`, `noir`, `vignette`, `invert`. They are a pass of the one Metal
  pipeline (§7.5), not Core Image: a second renderer would be a second
  thing for export to disagree with.
- `video.reflection` (M3): `null` or `{ "opacity": 0.35, "height": 0.5,
  "gap": 0, "falloff": 1.0 }`. `height` and `falloff` are fractions of the
  layer's cropped height so a reflection survives a scale change; `gap` is
  source pixels.
- `video.spotlight` (M3): `null` or `{ "shape": "rect" | "ellipse",
  "x": 0, "y": 0, "width": 480, "height": 270, "feather": 40, "dim": 0.6,
  "zoom": 1.0 }` — darkens the canvas outside the region and magnifies
  what is inside it (1–2×). Centre and box are SOURCE pixels from the
  cropped rect's centre. A *video* prop, not a shape one (§4.3's Shape
  pane first listed it): only the layer that owns the pixels can draw the
  zoom.
- `video.obscure` (format version 4): an ordered list of regions that HIDE
  what is under them — a face, a password field — each
  `{ "shape": "rect" | "ellipse", "x": 0, "y": 0, "width": 480,
  "height": 270, "feather": 20, "kind": "blur" | "pixelate",
  "amount": 1.0 }`, at most **four**, a shader budget exactly as
  `video.filters` is: the uniform block carries four regions and a fifth
  would be a control that hides nothing. Every value spelled there is what
  an omitted key takes, `shape` defaulting to `rect` and `kind` to
  `pixelate`. The box is the spotlight's own, so the two region controls
  put the same rectangle on screen; the kind and the amount are the
  opposite of a filter's half-strength blur, on purpose. A filter has to be
  visible without destroying the frame, while a region that only half hides
  has failed at its one job, and a blur at the shader's maximum radius is
  soft enough to read a large password field through — so the default is
  the kind that actually hides. `shape` is the spotlight's `SpotShape`, the
  same two shapes spelled once (`model_regions.rs`); `kind` is a closed
  vocabulary of its
  own and not a narrowed filter kind, so a hand-written `"sepia"` is
  refused on the way in rather than clamped later. The geometry is
  §5.3's source-pixel frame, so a region rides with its layer through
  scale, move and rotation; `amount` maps to the same maxima the blur and
  pixelate filters use. Where two regions cover one pixel the GREATER
  hiding wins and the other is not applied at all — a length in source
  pixels times the mix it would be applied at, a tie going to the pixelate
  — because both are a fresh sample of the raw picture and applying the
  second would put back what the first destroyed; adding a region can never
  make a frame less hidden, and a region at `amount` 0 is there and changes
  nothing. Written through `set_video` like any other video
  property — there is no obscure op.
- `video.blend` (format version 6): how this layer COMBINES with what is
  already on the canvas — `normal`, `multiply`, `screen`, `add`,
  `overlay`, `darken`, `lighten`, `difference`, a closed vocabulary
  refused by serde on the way in. `normal` is source-over and the default,
  which is what every project drew before the key existed, so an absent
  key, a zeroed uniform block and a recipe from an older core all mean the
  same picture. **The declaration order in `model_props.rs` is a
  contract** — it is the shader discriminant, as `ObscureKind`'s is, and
  `normal` is 0 with no `+1` offset, because a layer has exactly one blend
  mode and there is no empty slot to reserve. A mode may be added at the
  end; the eight may not be reordered. It belongs to the LAYER and not to
  a source kind: media, image, still, text and shape all draw through one
  fragment stage, so all five blend. Two rules are not in the schema and
  are stated where they hold — a clip mid-TRANSITION always draws
  `normal`, which the CORE forces into the recipe (§7.3), and a NEST clip
  may not carry a blend at all, which is an op's refusal
  (`edit_props.rs`'s `check_blend`) rather than a vocabulary one, since
  the value is legal and it is the clip that refuses it. A blend on a clip
  INSIDE a nest is allowed, and §5.3 records what it blends against.
- `video.motion` (format version 8): `null`, or up to three preset SLOTS —
  `{"in": {"kind", "duration"}, "out": {…}, "during": {"kind", "amount",
  "period"}}`. `in` and `out` are one of nine edge kinds (`fade`, `zoom_in`,
  `zoom_out`, `slide_left`, `slide_right`, `slide_up`, `slide_down`, `spin`,
  `pop`) over a DURATION measured from the clip's first and last frame,
  `text.animation`'s convention; `during` is one of five (`pulse`, `shake`,
  `spin`, `bounce`, `drift`) over the whole clip, `amount` 0–1 and `period`
  one cycle in ticks, which `drift` ignores. Both enums are closed and
  refused by serde on the way in; neither declaration ORDER is load-bearing,
  unlike `BlendMode`'s, because nothing crosses to a shader. Every field
  defaults, `null` being a clip that sits where it is placed, so an absent
  key means what every project meant before it existed.
  **It is not a value the compositor reads.** A preset says what a clip
  DOES, and the core turns it into PLACEMENT at render time (§5.3, §7.3) —
  the recipe publishes no `motion` key at all, and everything that EDITS
  rather than draws reads the clip un-moved (§5.4). Three rules are not in
  the schema and are stated where they hold: a `Motion` whose three slots
  are all null is NORMALISED to `null`, by the patch path and by the split
  rule, so one clip has one spelling of "no motion"; `in + out` longer than
  the clip scales both down to meet rather than refusing, because "too long
  for THIS clip" is a fact about a clip and a later trim would invalidate a
  refusal anyway; and a copy op decides which slots it may carry, since a
  preset is anchored to a clip's two ends and a copy has new ones (§6, and
  road map 5 §5e's table). The range checks are `props_check.rs`'s — both
  durations ≥ 0, `amount` 0–1, `period` at least one tick — and the ticks a
  PATCH carries ARE snapped by the core, after those checks, so a refusal
  names the number the caller sent (§6a; `period` floors at one
  FRAME rather than at the nearest grid point, because it divides in every
  `during` formula and has no zero). `text.animation`'s two timings are
  snapped the same way. A FILE is not snapped: it opens as what it says.
- `video.look` (format 15, §11 GR-7): absent, or
  `{ "kind": …, "amount": 0..1 }` — one of eight built-in looks, `kind` ∈
  `warm`, `cool`, `teal_orange`, `vivid`, `faded`, `vintage`, `dramatic`,
  `black_white` (closed, refused by serde naming the eight; the declaration
  order is the gallery's), `amount` 1 when left out and refused outside 0–1
  (`video.look.amount must be between 0 and 1, not 1.5`). `kind` has no
  default, so a `look` naming only an amount is refused on a clip with none.
  It is **written only when a clip has a look** and is the video group's last
  key, so a look-less project's text is unchanged; `null` in a patch removes
  it. What each kind IS — Color's four, Light's nine and a split tone — is
  core data (`model_look.rs`), published in the recipe's `look` (§7.3) and
  baked by the compositor (§7.5). In an action's end `amount` interpolates
  and a change of `kind` switches at the end; an end whose merged look has no
  `kind` evaluates as no look and keeps its other keys (§5.4).
  **A `.cube` LUT** (§11 GR-8): `kind` also takes `lut`, with `media` — the
  LUT's media id, stored between `kind` and `amount` and written only with
  `lut` — required (`video.look.media is required with kind lut`), naming a
  `lut` media of the project (`video.look.media 99 is not a media of this
  project`, `video.look.media 3 is a video media, not a lut`), and refused with
  a built-in kind (`video.look.media goes with kind lut, not warm`); a patch
  naming a built-in kind and no `media` drops a stored one. `media[].kind`
