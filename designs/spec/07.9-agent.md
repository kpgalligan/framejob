# 7.9 Agent

`agent.rs` is copied from Rasterize (generic streamable-HTTP MCP, tools
only). Catalog: one tool per §6 op with the same name and arguments —
**each of which also takes `scope`, the envelope key of road map 2's phase
9** (§6), injected from ONE line in `AgentCatalog.tool(...)` gated on the
core's own `rc_op_names`, so a new op gets it for free and cannot drift, and
enforced by a fourth part of the startup parity check, which is the only
mechanism in the tree that would catch an op tool declaring none.
**All fifty-nine op tools PRINT those arguments rather than
restating them** (road map 7's D3·3 for the clip group, D3·4 for the rest):
`AgentCatalog.opTool(...)` takes the
tool's prose and a sentence per argument and merges the structure — kind,
constraints, closed vocabulary, required list — in underneath from
`rc_op_schemas`, so **the core says what an argument IS and the catalog says
what it is FOR**. Where a tool deliberately accepts more or less than its op
does — a bare-string body, the string spellings of a boolean, a null that
MEANS something, a range the core clamps to rather than refusing, a default
taken from the playhead, a list the tool will not take empty, an argument
only the app can fill and so does not publish (the two graphic ops'
`schema`, read from the module's current revision, road map 10's G3b) — the
difference is a row of `AgentCatalog+Declarations.swift` with the op, the
argument, what the app adds and why, and the schema declares it, so an agent
can SEE a shorthand rather than discover it. What still declares a schema of
its own is the twenty-six APP-STATE tools, which have no op to read one from.

**A fifth part of the startup parity check holds that identity up**
(`AgentServer+Parity.swift`, road map 7's D3·5). For every op tool the
declared argument names must be exactly the core's for that op, plus the
injected `project` and `scope`, plus whatever a declarations row names, less
an argument a row says the app fills — in
both directions, so an argument the core has that no tool declares and an
argument a tool declares that no op has are each named with the op, the
argument and the side, and a declarations row naming an argument the core has
not got is named as stale. Because the catalog prints STRUCTURE and writes
only PROSE, the same part also complains about an argument that would reach an
agent with no description at all, and about a description written for an
argument the table has never heard of, which is how a misspelt prose key is
caught rather than dropped in silence. App-state tools are skipped by the same rule
part 4 uses — the core's own op list, which has no row for a tool with no op
behind it. What no comparison of two lists can see is a
CALL. A call's KEYS are compared to the tool's published schema at the
dispatch — the argument gate, kpgalligan/reelcut#21, for all eighty-five
product tools — so a name no tool published is refused naming the tool and what it
takes, where it used to be dropped in silence; and that an argument the
catalog prints is one a hand-written handler really reads is put to the
running binary by `tools/proof/op_argument_proof.py`, one left-out argument
per op.

The scope is read ONCE per call, at the dispatch, and an op with no `scope`
of its own follows the nest the app has OPEN — a call and the window agree
about which
container they mean, or `get_project` would list clips the very next op could
not name. An EXPLICIT scope outranks the open view. Plus
`set_scope {nest?, clip?}` (the mirror of the double-click and Clip ▸ Open
Nest, and what lets `render_frame` and `get_project` look inside a nest at
all; `clip` is the precise spelling, since a nest may be shown by two clips
at two different starts, and neither argument means the timeline),
`open_project {path}`, `new_project {path?}`, `import_media {path}` →
media id, `save_project`, `get_project` → the JSON, `set_playhead`,
`set_range`, `set_selection` and `undo` / `redo` (the view state and the
history are app state, not ops, but without a setter for each the "one
edit is one undo step" and "the in/out range scopes the export" properties
cannot be checked by driving the built app),
`import_captions {path, track?}` and `consolidate_media {}` (M3's two
§5.6 file features),
For `transcribe(engine: "assemblyai")`, the handler validates typed arguments
and the target before the coordinator decides whether a keyless run can reuse
every packaged transcript. Keyless calls resolve no endpoint; a mixed or stale
batch is refused as a whole with no request or edit. Successful placement is
one grouped undo step, and `place: false` only returns cues. Deferred remote
deletions are named in `note` on success and in the error on failure.

`record_screen {seconds, display? | window?, microphone?, system_audio?,
show_clicks?, rate?, size?, place?, path?}` (road map 3 — File ▸ New
Recording…'s mirror: the file lands as ordinary media at the playhead of
the target document, or as an untitled document rated at `rate` when
nothing is open; it reads the Screen Recording and Microphone grants
synchronously and NEVER prompts, and its refusal order is the caller's own
mistakes, then the grants, then the display or window lookup, which cannot
be asked without them; pausable from the menu bar's item while it runs,
the result then carrying `pauses` and `segments` — one entry per file,
ALWAYS present — with `duration` the TOTAL recorded and the top-level keys
the first segment's),
`detect_silence {clips?, mode?, voice_confidence?, threshold_db?,
min_length?, padding?}` → the
quiet spans of the timeline and the scope they were taken over, which
`ripple_delete_ranges` then cuts — the one tool that reads a CACHE rather
than the model, and the only app-state tool that neither edits nor moves
anything (it is the sheet's own detector, so an agent and Clip ▸ Remove
Silences… propose the same cuts). A moment is quiet where every clip in
scope is quiet there, measured as the file's peak times the mix envelope
(§7.2), and two things are never in a candidate: a clip the mix has
SILENCED, which is dropped from either scope rather than read as quiet —
it covers its span while passing the test at every tick, so a muted music
bed would otherwise propose one cut across the whole song and take the
voiceover under it — and a NEST, whose sound counts toward the test but
which no candidate may intersect, because `Source::Nest` has no in point
and splitting a nest clip strands its tail (§4.4's round trip is how the
dead air inside one is reached). `mode` is road map 4's S1 — `voice`, the
default, judges by the cached Silero VAD probability against
`voice_confidence` (0.1–0.9, default 0.5, refused in `level` mode) and falls
back to the level rule over any clip whose own source window holds no voice,
naming those media in `judged_by_level`; a media whose speech cache has not
landed is named in `voice_pending`, is never quiet BY THE MODEL and is not
judged by level either — though the mix's own gain floor can still make it
quiet, which is why the note beside `pending_peaks` promises nothing about a
media this answer already proposes a span inside — and is folded with the
waveform waiters into `pending_peaks`,
`transcribe {clips?, language?, place?, engine?, speakers?, vocabulary?,
refresh?, style?, replace?}` and `export_captions {track?, path, format?}`
(road map 2's phase 4 — the mirrors of File ▸ Generate Captions… and File ▸
Export Captions… — with `transcribe`'s `engine` … `refresh` road map 6's C1
and `style`/`replace` road map 8's W4a). `style` is `subtitles` (the
default, today's cues) or one of the five word caption styles —
`highlight`, `pill`, `karaoke`, `build`, `one_word` — a misspelling refused
with the six named; under a word style each result cue adds `words`
(`[{start, end, text}]`, timeline ticks) and `size` where a lone word
shrank, and the placed pages carry the style's face, `case`, `word_style`
and the words in clip time. `replace: true` removes, in the same undo step,
every caption track this command could have made over the scope (named
"Captions" or "Captions N", only text clips, each overlapping a clip being
transcribed) and the result lists them under `replaced` whenever `replace`
was given; it is refused by name with `subtitles` or with `place: false`.
`transcribe` returns the cues in TICKS whether or not it placed them —
`place: false` is a read, like `detect_silence`, and registers no undo
step — and reports every named clip it could not read under `skipped`.
It has TWO engines. `engine: "apple"` is the default and is the on-device
recogniser; `engine: "assemblyai"` uploads the WHOLE audio of every media
file behind the named clips to AssemblyAI, and `speakers`, `vocabulary` and
`refresh` apply only to it — each refused BY NAME under `apple`, because an
argument that cannot do anything is a mistake and not a no-op. The default
is never what the sheet last chose (§11's R6-2). The refusal ORDER is the
caller's own mistakes first — an unknown clip, an empty scope, a misspelt
`engine` with both spellings named, a cloud-only argument under `apple` —
then the credential, and only then the network. (**Corrected 2026-09-21** by
road map 6 §10.13's reader review, which also corrected §5g's twin sentence:
this used to name "a media over AssemblyAI's ten-hour limit" between the
credential and the network. That limit is not a position in a RUN's order —
it is one MEDIA's problem, checked at the head of its own fetch and therefore
after every earlier media's whole round trip, and reported under `skipped`.
It refuses the run only when it is the only media there is. MEASURED.) The cloud result gains `engine`, `uploaded` and `cached`
(media ids), `audio_seconds` (what was billed), `speech_model_used`,
`language_detected` with its confidence, and `note` when there is something
to say — a vocabulary that was capped, R6-8's fallback, or a remote delete
still owed. The on-device engine (`SpeechTranscriber` since road map 8's W2,
§11 W-8) needs no grant and has no length ceiling, so its result carries no
`truncated` and no `note` — neither engine's does. Its models are installed
per Mac: a language whose model is not installed is REFUSED by name ("a
person has to install it"), and the tool never downloads one — a download is
a person's act, from the sheet's Download row. `export_captions` never guesses its track: with no all-text track,
or more than one, it refuses and lists the candidates by id and name — the
posture `remove_media` and `export` already take when an answer is not
unique — and it edits nothing, so it registers no undo step either.
`render_frame {t, max_width?, path?, format?, burn_in_timecode?}` → a PNG,
JPEG or HEIC (the verification hook: the compositor renders offline through
an `AVAssetImageGenerator` over the same composition + video composition).
With no `path` and no `format` it writes a `.png` to a temporary file and
ends its text `Written to <path>.` exactly as it always has, which five
proof scripts read the path back out of; an explicit `format` wins over the
path's own extension and the extension is REPLACED rather than appended to.
The write is `FrameWriter`'s — the one function File ▸ Save Frame… calls
too, which is what makes those two files byte-identical by construction
rather than by luck, and the only way the line can be checked at all, since
no script can press a save panel. `burn_in_timecode` is the recipe option of
§7.3 and not an export override, and this tool is the only one that can
photograph a burn-in. When a graphic in the frame warned or failed, one
sentence per report precedes that last one — `Graphic "x" failed at frame
N: <message> (line L, column C).`, `… warned at frame N: …` or `… does not
compile: …` — and a failed graphic draws its error card in the picture
(road map 10's G3c); the call is still not an error, and
`normalize_clip {clips, peak_db?}` (road map 2's phase 5 — the mirror of
the Audio section's Normalize button and Clip ▸ Normalize; it is a
composite the UI offers as one command, not an op, and it reports each
clip's measured peak and the volume it wrote, with what it could not
measure under `skipped`), and
`export {preset, path, size?, range?, video_bitrate?, audio_bitrate?,
loudness_lufs?, peak_dbtp?, burn_in_timecode?}` — the export sheet's
controls in the sheet's own vocabulary (all but the frame rate: the tool
exports at the document's, or on GIF and APNG at the format's cap), so an
agent export and a menu export can ask for the same file. Its result
carries what the file's sound MEASURED — integrated loudness, true peak and
the gain that was applied — for every export that has any, asked for or
not, which is `detect_silence`'s posture applied to the writer and is what
makes the ±0.5 LU claim checkable over MCP.
`burn_in_timecode` is the one argument of the nine that is not a setting:
it is a recipe option (§7.3), travelling beside the resolved settings rather
than inside them, because the override table ignores a key it does not
know — an option posted that way would vanish without a word and the tool
would report success on an un-burnt file. The result echoes it back for the
same reason.

**Lenient decoding is for what the CORE wrote; nothing a caller wrote is
decoded through it** (deepening D1): a patch, a colour, a region and a new
clip's text or shape go to the core as the caller's own object, and the core
is the one validator of what each may carry (§5.2, §6) — the agent door
checks only what the core cannot know, which is the target, the scope, an id
against the container it names, a time, and that a required argument was
passed at all.

**The graphics loop** (road map 10's G4a): `write_graphic {name, source}`
writes `graphics/<name>.js` through the store's one writer (atomically,
creating the folder), rescans at once and answers the compile of THAT text —
`ok`, `meta`, `schema`, `diagnostics [{level, message, line, column,
frame}]`, `clips` — where a module that does not compile is an answer, not
an error; the write is not undoable and never dirties the document (G-3),
and a bad name is the core's sentence. `get_graphic {name?}` reads one
module back (its source, revision and compile) or, with no name, the folder
— its path whether or not it exists yet, and every module with its revision,
`ok` and `clips`. `graphic_reference {}` answers the bundled
`GraphicsAPI.md` verbatim and needs no open project. `get_project` gains
`graphics: [{name, revision, ok, clips}]`, always present. The reference is
also written into an EXISTING `graphics/` as `API.md` and `API.d.ts` (never
a reason to create the folder, G-14, and not content that makes an untitled
root worth carrying). `get_graphic {}` also lists `families` (the engine's own
names, `rc_graphic_library_families`) and `assets`.

G4b adds three. `render_graphic {name, frames | frame, props?, width?,
height?, max_width?, background?, format?, path?}` draws a module WITHOUT a
clip, on the server thread: the ctx a clip would get (the canvas's fps,
`durationInFrames` from `meta` else 5 s, the size from the arguments, else
`meta`, else the canvas), up to 16 frames on a contact sheet — the cells
scaled down to `max_width` (default 2048), never the 8 px gaps or the 24 px
label strips, a failing frame drawn as its error card — written through
`FrameWriter` as a PNG, with one sentence per frame that failed or warned
before "Written to <path>."; `format: "svg"` answers one frame's SVG, its
diagnostics and its ctx. `import_graphic_font {path}` copies a `.ttf`/`.otf`
into `graphics/fonts/` through the store (G-14), rescans, and answers
`families` — the family names the ENGINE reads from that file, from a
throwaway library holding it alone, because CoreText names some files
differently — and `library_families`; a file that loads no face is refused
in the engine's words. `import_graphic_asset {path, name?}` copies a PNG,
JPEG, GIF, WebP, SVG or SVGZ into `graphics/assets/` and refuses anything
else and an empty file. Both are not undoable and never dirty the document.

G5b gives the person the same doors (§9): File ▸ Add Font to Graphics… and
Add Image to Graphics… run the two imports' own body
(`GraphicStore.importFont` / `importAsset`), Help ▸ Graphics Reference opens
the file `graphic_reference` answers, and **Insert ▸ Graphic is
`write_graphic` of a template (or a chosen `.js`) then `add_graphic_clip`**
— one undo step, "Insert Graphic", placed by Add Text's rule (§11 G-16).

**Dev tools** (§11 V-1..V-3, road map 11). A tool compiled only under
`REELCUT_DEV_TOOLS` — set for Debug and Release, never for Distribution, so
`make dist`'s binary holds none of their code (`dist_check.py`). A dev tool
is an ORDINARY tool: a handler and a catalog row from
`AgentServer+DevTools.swift`, spliced in before the file tools, covered by
the parity check and the argument gate like any other, and counted apart
from the eighty-five product tools (`tools/proof/dev_tools.py`).
**`snapshot_ui {window?, view?, appearance?, path?, fill_preview?, layout?}`**
is the first. With no `window` it lists the visible windows (kind, class,
title, frame, content size, scale, occluded, key, main, the editor's project,
any attached sheet). With `window` — `editor`, `sheet`, `settings`,
`welcome` or `recorder` (the New Recording panel, found open and never built by
the call) — it captures through `cacheDisplay` (V-3), which needs neither an
active app nor a visible window, as an image block plus a JSON text block
and a PNG on disk; `view` narrows the editor to `toolbar`, `preview`,
`inspector` or `timeline`; `appearance` is REFUSED whatever its value,
naming the launch-time way (road map 11's V3: a live switch left the colours a
view took when it was built in the launch appearance, so the picture was a mix
the app never draws) — the look is the instance's, set at launch by the
dev-only default `-RCDevAppearance light|dark`, which puts `NSApp.appearance`
before any window is built, and every capture answers the `appearance` it drew
in; `fill_preview` (default true) puts `render_frame`'s picture at the
playhead under the canvas overlay for the capture and takes it out after;
`layout` (default true) writes `<name>.layout.json` beside the PNG — every
view's class, identifier, frame in capture points, hidden, ambiguity,
intrinsic size and label text (never a secure field's) — and answers its
`problems` (ambiguous layout, a view past its superview, a truncated text
field), AppKit's private `_NS…` views counted apart. It runs on the server
thread; a file-panel sheet is refused, since it would capture as one colour.
**`perform_menu_item {path?}`** runs a main-menu item by its titles, e.g.
`["File", "Export…"]`, as the menu shows them (a validator may retitle one:
Undo reads "Undo Add Marker"). It is delivered to the NAMED project's editor
window's own responder chain — the first object from its first responder
down, then the window, its delegate, controller and document, then the app,
its delegate and the document controller, that answers the action — never
nil-targeted, so it works with the app inactive and the window covered
(road map 11's V2b, measured). With no `project` it is the frontmost
project's window, or the app's chain alone when none is open; app-level
items (Settings…) resolve at the chain's tail. The action runs inside one
explicit undo group on the window's document, so an edit it makes is one
undo step. It answers after a settle: the attached sheet, the app-modal
window and the visible windows read every 20 ms until five reads agree,
bounded at 3 s — so a sheet that arrives a turn later is in the answer —
with the target, `perform_ms`, `settle_ms`, the sheet, the windows opened
and closed, the modal window, `active` and the window's facts. Refused by
name and running nothing: an app-modal window already up, an empty path, a
title not found (the level's titles listed), a submenu, an item with no
action, a selector the allow-table (`UIMenuTable.swift`, a mirror of
`tools/proof/capture_spike/inventory.json`) reads `framework` or `modal` or
does not list (`unclassified`), an action nothing in the chain answers, and
an item its own validator disables. With no `path` it lists every leaf:
path, selector, verdict, refusal, enabled, state, hidden.
**`cancel_sheet {}`** closes the sheet attached to a project's window the way
its own Cancel would — a file panel is ended with `.cancel`, any other
sheet's Escape button pressed, or its only button — and refuses anything
else, naming the buttons; it answers after the same settle.
**`select_inspector_tab {tab?, sub_tab?}`** (road map 11's V3) picks the
inspector's tab — `clip`, `media`, `document` or `assistant` — and, with `tab: clip`, the
Clip tab's sub-tab — `text`, `shape`, `graphic`, `picture`, `sound` or `clip` —
in a project's editor window, through the calls the two strips' clicks make
(`InspectorViewController.select(_:)`, `selectClipSubTab(_:)`), so what
`snapshot_ui` captures is what a click shows; the pick is forgotten when the
selection changes, as a click's is. With no `tab` it changes nothing. It
answers `tab`, and on the Clip tab with a selection the active `sub_tab` and
the `sub_tabs` on offer (else `null` and `[]`). Refused, leaving the inspector
as it was: a value outside either list, a `sub_tab` without `tab: clip`, a
`sub_tab` with no clip selected, a project with no editor window, and a
`sub_tab` the selection does not have (the refusal lists the ones it has).
**`assistant_send {text, timeout?, pane?}`** and **`assistant_answer {answer,
timeout?, pane?}`** (road map 12 A1) drive a project window's assistant session
(below): `assistant_send` types `text` into it, opening the session on the
first call, and `assistant_answer` answers the ask-first question it stopped
on — `allow` or `deny` — or `stop`s the turn. Both wait, releasing the
lane's lock (`AgentLane.releasingLock`, since the turn's own calls need it),
until the turn is no longer busy or `timeout` seconds pass (default 120,
1…600), and answer `state` (`finished`, `asking`, `closed`, or `running`
past the timeout), the pending `question` (tool, path, exists, sentence) or
`null`, the streamed `text`, every event since the call but the text and
progress deltas, and `waited_ms` — never the key or the model. Refused by
name, changing nothing: a project with no editor window, a send while a
turn runs, allow or deny with no question pending, stop with no turn
running, an answer to a window with no conversation, an `answer` outside
the three, a `timeout` outside 1…600, an empty `text`, and a session that
cannot open (its own sentence). Both run on the server thread. A turn in a
launch WITHOUT the server is the dev-only launch default
`-RCDevAssistantSend <text> -RCDevAssistantReport <path>` (both from the
argument domain): after launch it opens an untitled project, sends `text`,
waits up to 120 s, reads `get_project` through the lane pinned to that
project, writes one JSON report (`ok`, `error`, `server_running`, `state`,
`text`, `events`, `get_project`) and closes the session.
With **`pane: true`** (road map 12 A2) both go through the Assistant tab's own
controls instead: `assistant_send` sets the composer (ending any edit) and
clicks Send, refused if the composer still holds the text after;
`assistant_answer` calls Allow's or Deny's own `mouseDown` with a left click
at its centre, or clicks Send while it reads Stop. The order is the target,
then (with `pane`) the control in a window and not hidden — else refused by
name, `… select_inspector_tab {tab: "assistant"} first`, opening and changing
nothing — then the session and the refusals above.

Handlers use `performGroupedEdit` so off-event edits get their own undo group
(Rasterize's `AgentServer.performGroupedEdit`). Default port 4817; env
`RC_AGENT_PORT`; launch flag `-AgentServerEnabled YES`.

**The lane** (road map 12 A1; §11 AI-2, AI-3, AI-5, AI-7, AI-12). Every tool
call goes through `AgentLane` (`AgentLane.swift`): the MCP trampoline's
`serve`, on the server thread, and the assistant session's `submit`, which
returns at once and answers on the lane's serial queue. One `NSLock` admits
one call at a time from either caller, which is what keeps `callScope` and
`callDocument` race-free; it is never taken on main. The lane runs an
`offMainTools` member in place and every other tool on main.
`AgentServer.prepareCatalog()` builds the catalog, fills the argument gate
and runs the parity check once per launch, from `main.swift` before
`NSApplicationMain`, so the gate is full whether or not the server is ever
started; `start()` takes its memoised string. A `submit` is pinned to its
window's document (`callDocument`, which `targetDocument` checks first): no
`project` argument means that document, and a `project` naming another is
refused by name. `AssistantToolTable.swift` is AI-7's one table: the dev
tools, `record_screen` and `transcribe` with `engine: "assemblyai"` are
withheld and refused by the lane; `export`, `export_captions`, `save_project`
and `consolidate_media` are put to the session's ask-first hook BEFORE the
lock, naming where they write and saying REPLACES when a file is already
there, and a Deny answers "The person declined: …" without running the tool.
An MCP caller is never asked and never refused by the table. **A call that
arrives while any open document is mid-gesture waits for mouse-up, then
runs** (AI-12, #144): every main hop, `onMain` included, is
`AgentLane.onMainWhenIdle`, which retries every 20 ms while a timeline,
canvas or inspector-slider gesture is live, so the call lands as its own undo
step above the gesture's; called on main it runs in place.

**The assistant session** (road map 12 A1; §11 AI-1, AI-4, AI-5, AI-7, AI-8,
AI-11, AI-13). Each editor window has at most one `AssistantSession`
(`AssistantSession.swift`, a port of Rasterize's `AssistantHelperSession`),
held by the window's controller and closed with the window. Opening one
checks, in order and each refusing in its own sentence: the base-URL override
`RC_ASSISTANT_BASE_URL` (AI-13; plain `http` only for a loopback host), the
person's key (`SecretStore`'s `anthropic-key`, then `ANTHROPIC_API_KEY`;
with the override set and no `-RCSecretFolder` no key file is opened), the
catalog prepared at launch (read, never prepared: AI-3), and the bundled
helper `Contents/Helpers/reelcut-agent`. The helper runs with exactly
`HOME`, `TMPDIR` and `PATH=/usr/bin:/bin`; its first stdin line is
`configure` with the key, the model (`ReelcutAssistantModel`, else
`claude-opus-5-5`, AI-11), the system prompt, the assistant's catalog
(`AssistantToolTable.assistantCatalog`), the core tools
(`get_project`, `render_frame`, `undo`, `redo`, loaded up front; every other
tool is found by tool search), the search guide, the compaction
instructions, the chat settings and, when set, `api_base`. The key is in
that line and nowhere else. Every tool the helper asks for goes through
`AgentLane.submit`, pinned to the window's project, ONE at a time in the
order asked; each result is spliced verbatim into a `tool_result` line, and
every write goes through one serial queue. An ask-first call is a pending
question the person answers Allow or Deny; Stop, closing the window, the
helper's death and the session's release each answer it as declined, so
every question the lane asks is answered exactly once. Stop also answers
every call not yet run "Cancelled by the user." (a call already running
finishes). A dead helper closes the session, and the next send opens a new
one.

**The prompt** (road map 12 A3; §11 AI-7, AI-9, AI-15). The system prompt,
the tool-search guide and the compaction instructions are Swift literals in
`AssistantPrompt.swift`, fixed for the session: they interpolate the
timescale (`ReelTime.perSecond`), the ask-first and conditional withheld rows
of `AssistantToolTable.rows`, the shared id kinds and the context tag, and
the guide renders `searchTopics`' words, which cover every tool of the
assistant's catalog but the core tools exactly once. What changes between
turns rides on each person message instead (AI-15): `send` writes the text
behind a `<reelcut_context>` block (`AssistantLiveContext.swift`) of the
project's name and path, the open nest, the playhead in ticks and seconds,
and the selection, each label a key of `get_project`'s answer. `make test`
runs `tools/proof/assistant_prompt_proof.py --probe`, whose rows F1–F7 check
the texts against the code — every backticked token a tool or a path of
argument names and `get_project` keys, no withheld tool named, the
timescale, the id kinds against a fixture, the topics against the catalog,
the ask-first rows, no blank line and the length bounds, the context block
exactly — and M1–M4 make each checker fail on a mutated copy.

**The Assistant tab** (road map 12 A2; §4.3, §11 AI-4, AI-8, AI-11, AI-14) is
the person's door to that session: the inspector's fourth tab, and View ▸
Assistant ⌃⌘A to show it. The composer's Send is `assistantSend` on the
window's controller, which opens the session (an open failure is an error
line in the transcript) and sends while idle; the transcript is the
session's `onEvent` stream mapped to entries (`AssistantTranscript`), kept on
the controller; Allow, Deny, Stop and Clear are `answer`, `cancel` and
`close`. Settings' Assistant pane holds the key and the model; a Save,
Remove or a model that actually changes ends each window's conversation,
since a session keeps what it was opened with. **None of it has an MCP
mirror, deliberately:** showing the tab is view state, which the dev tool
`select_inspector_tab {tab: "assistant"}` covers in a Release build; the key
and the model are the person's settings, which no tool reads or writes
(AI-8, AI-11); and the conversation itself is the assistant's, whose calls
already ARE tool calls through the lane. `assistant_send` / `assistant_answer`
with `pane` drive the tab's own controls for a proof.
