## Context

The assistant's helper was `Contents/Helpers/framejob-agent`, TypeScript compiled by Bun from `agent/src/` on `@anthropic-ai/sdk` ^0.128.0's Tool Runner (road map 12, AI-1): 57,735,840 bytes, signed with JavaScriptCore's `allow-jit`, listed in the notices with Bun's LGPL-2 JavaScriptCore and WebKit (#380), and kept byte-identical to Rasterize's `agent/src/` by a rule nothing checked. Unlike Doctored's, its pricing was live (road map 13): it priced every response and the app showed the person two figures (P-7). The owner asked on #599 (2026-11-12): "We're going to replace Bun with the Swift Anthropic API we wrote. See ~/devel/doctored for background info. That had the same Typescript Anthropic API, but now uses our new Swift API." The decision comment, posted the same day: "#599 Reference doctored for the design". The road map was written from Doctored's record of the move (its AH-1..AH-7, read at Doctored's `b524babc`, with `33af04c1`, the Swift helper in and the Bun helper out, and `0bb54fc2`, the system block's breakpoint) and found that Rasterize is Doctored (`~/devel/rasterize` is a link to it), so the byte-identical rule described a directory that no longer existed. The owner approved it on 2026-11-12: "For Bun replacement, Slaude changes. I would like you to push changes to Slaude, not just make them locally. They can be a PR. Everything else, as recommended". So the six questions were answered: pricing ported into the helper (1 (a)); the package Frame Job's own, with no identity rule (2 (a)); all three paid proofs after the deletion (3 (a)); agents make a Slaude change themselves, as a branch and a pull request the owner merges, only when a measurement shows the pin cannot serve (4, not as recommended); the build cost accepted (5 (a)); the breakpoint adopted with the switch (6 (a)). No phase needed a Slaude change. (orig head, §2, §3, §12)

## Decisions

- **A process, not a linked module (SA-1, Doctored's AH-1).** The app builds in Swift 5 mode and `make typecheck` and every probe compile `app/Sources` with no extra module, so it cannot link Slaude, which is `async`/`await` throughout; a helper crash still cannot take a document down, and the key still arrives only on stdin in a scrubbed environment. The helper keeps its name, its place and the stdio protocol, so `AssistantSession`, `AgentLane`, `AssistantToolTable`, `AssistantPrompt` and `AssistantSpend` changed in comments only, but for one option (below). (orig §2, §3)
- **Slaude is a SwiftPM dependency of `agent/` alone, pinned by exact revision (SA-1).** Not vendored: 2,385 Swift source files at the pin would sit under the name check, the size ledger and every grep for no gain. Not copied piecemeal: its client, stream and retries are tested whole (about 3,800 tests, Doctored's figure). The pin is `4c6c2ca4`, Doctored's and Slaude's `main` on 2026-11-12 (`"identical"` in SA0's compare). (orig §7, SA0 item 10)
- **`.macOS("26.0")`, in the string form (SA-1).** `.v26` is refused under swift-tools 6.0 (`'v26' was introduced in PackageDescription 6.2`); the string form is accepted. (SA0 item 1)
- **Its own turn loop (SA-2, Doctored's AH-3).** Slaude's runner runs tools one at a time and rethrows a cancel out of a tool, which can leave a `tool_use` with no result and fail the next request. The loop asks every `tool_use` of a response at once, answers every one before the next request, never ends a tool wait on a cancel and has no timeout on one, which is what lets AI-7's ask-first hold stay in the app. The history is replayed byte for byte and each body is raw JSON in a pinned key order. (orig §4)
- **Compaction is one explicit rule (SA-4).** Success needs the `compaction` stop and a non-empty summary. Three of the runner's behaviours changed by design: a final reply's unrun `tool_use` blocks answered at once, no summary after such a reply, and an empty summary a failure, not a swap. SA2's comparison found (b) was no difference (the 0.128.0 runner already skipped that summary), (c) differed in events only, and a fourth: a summary holding a non-empty block that stopped with another reason, which the runner swapped in and the Swift helper keeps out, allowed by name. SA1's diff read found the limit read at the turn's start; it is read at the turn's end, as AI-20 says. #484's sentence stays, where Doctored's helper drops it. (orig §5, SA1 and SA2 records)
- **Pricing ported, and P-8's bound unmoved (SA-3).** The price function and the table with its refresh answer the same fixtures (`agent/prices/cases.json`, all 23 within 1e-12; `reduce_cases.json`). The table is compiled in with `.embedInCode` through a committed relative link in the target: named outside the target SwiftPM printed `Found unhandled resource` on every build, and a copy would drift from `make prices`'s file. A cut response is priced from Slaude's `currentMessageSnapshot`: a drop after `message_start` read input 100 and output 0, a cancel after `message_delta` 100 and 10, and the two errors are distinct types, which is what tells H10's cut from H11's Stop. (SA0 items 4 and 5)
- **The request (SA-5).** The system block carries its own `cache_control`, so a new conversation and the first request after a compaction read the tools-and-system prefix instead of writing it (Doctored measured about 9,700 tokens). That only works if the bytes repeat, and the app's `configure` did not: two launches wrote 396,901 bytes each, equal once parsed, differing in key order at every level (101 of 122 tool entries), so the Bun helper's prefixes differed too. `AssistantSession.write` took `.sortedKeys`, the road map's one app behaviour change; KO then read the two launches' prefixes identical. API version `2026-10-21` and `Authorization: Bearer` are Slaude's. (SA0 items 7 and 8, SA1 item 6)
- **The protocol (SA-6).** `reset`, which nothing sends, is dropped; `message_done` (H10 needs it to be able to fail) and `ready` (P3 waits for it) stay. Every wording that differs from the TypeScript is listed by name, e.g. `API error: <message>` where the TypeScript wrote `API error : <message>`.
- **Two concurrency models, kept apart by directory (SA-7).** W-8 names files, not a directory; `app/Sources` gained no `async` and `make typecheck` kept its four warnings.
- **The suite on its own scratch path, emptied when its marker names another (SA-12).** Every lane copies `build/`, and SwiftPM cannot build on a scratch path made elsewhere: a cloned warm suite path failed in 23 s with 2,386 "PCH was compiled with module cache path" lines; through the guard it was emptied, built cold and passed in 175 s, then in 8 s. (SA1 item 3)
- **The build: Doctored's script with three rules (SA-8).** SwiftPM in release, in batches, without whole-module optimization, in a scrubbed environment, stripped and signed with the hardened runtime and no entitlements (Doctored's AH-6). SA0 found three rules it lacked: the table's content in the stamp's key (a digest of `agent/Sources` without following links misses it); the scratch path's own path recorded beside the key, read only on a miss, so a clone is served at any path (1.21 s) and a moved one that misses is emptied (SwiftPM failed on it, `PCH was compiled with module cache path`); and the tree taken from `$PROJECT_DIR`, because a tree copy's `tools` is a link. (SA0 items 3, 4 and 9)
- **A helper mutant is built on one persistent mutant tree (SA-8).** On a clone of the tree's scratch path a changed `agent/` could not be built at all (298 PCH errors, SA0 item 9). SA0 measured a direct `swiftc` build against the tree's Slaude objects at 15.39 s, but on a package with no embedded resource; SA3 chose `build/agent-swift-mutant/`, built by the same script, cold once per worktree (158.0 s in SA3's, 95.6 s in SA4's) and 5.4–14.8 s a mutant after, so a mutant compiles as the product does. (SA0 item 9, SA3 and SA4 records)
- **B1 measures the built helper's first POST (SA-9).** The hand mirror of the wire shape P-9 (d) accepted is deleted: 399,414 bytes plus 30,000 for the conversation is 429,414, within 480,000. (SA3 item 4)
- **The notices moved with the switch (SA-10).** The npm reader read `agent/node_modules`, which only the Bun step's `bun install` made, so the notices could not outlive the step. Slaude is `package slaude <revision>`, read from the resolved checkout as Sparkle's is, with Slaude's `LICENSE` and the vendored SDK's `LICENSE` and `LICENSE-MIT`; the Bun entry and the LGPL notice went, and #380's review with them. (orig §2, SA3 item 5)
- **Frame Job's package is its own (SA-11).** Owner's answer 2 (a): ported once from Doctored at `b524babc`, with no identity rule and no checker, "a shared rule with no checker is the kind that rots". Rasterize's two hand-over issues had nothing left to apply.
- **Two helpers compared, then recordings (SA2, SA-13).** SA2 ran both helpers over 27 scripted cases and compared every event and every request with its key order; sixteen allowed rows, each shown needed (`--rows-needed`) and none vacuous (`drive-same-helper`: every row "allows nothing", 27/43). No body differed in key order, so key order is compared strictly. Once the Bun helper went, a case's `expect` held only types and counts while five of the eight mutants change only a body, so each case is held to a recording written from the last two-helper run that passed (43/43), under three comparison rules, and `--record` refuses a failing run. (SA2 and SA4 records)

## Known limits

- **No figure here is an idle one** (orig §10): costs to plan with, not thresholds.
- **Doctored's figures stand for the network fetch of Slaude, whole-module optimization and the publish runner** (279.5 s to build Slaude and the helper on `macos-26`, the archive 20 min 2 s against 19 min 11 s for the last Bun build). Whole-module optimization is not used (release in batches); the fetch and the runner are what the owner's next publish shows.
- **API version `2026-10-21` is measured for what the three paid proofs send**: every POST answered 200. A request only some other conversation would make is not.
- **`x-stainless-timeout: NOT_GIVEN`** goes out on every request (#614): the API accepts it, and SA-13's recordings hold it by value.
- **The compile and the disk**: a worktree's first build compiles Slaude and needs the network; a lane that copied `build/` builds the suite's debug Slaude cold once (SA-12), and a cloned release scratch path that misses builds cold (SA-8); SA3's three scratch paths held 1.6, 1.7 and 2.1 GB (SA3 item 1).
- **A Slaude re-pin or a toolchain that changes a request, or a `make prices` refresh that moves a `cost`, fails `make test` until re-recorded** (SA-13); a price-table edit also rebuilds the helper, which the stamp forces (SA-3).
- **Slaude is young and has one maintainer**, the owner; the pin moves only in a commit that runs the suite and the gate, and a pin on a pull request's branch must keep that branch until Frame Job re-pins (orig §11; no such pin was needed).
- **A fix Doctored makes to the loop both share reaches Frame Job only when a phase here ports it** (SA-11).
- **A client that sends `reset` hears nothing** (SA-6).
- **Two concurrency models in one tree**, kept apart by directory (SA-7).
- **The paid acceptance's figures are printed to four places from unrounded sums**, so its three settled figures add to $0.5456 against the ledger's $0.5457.
