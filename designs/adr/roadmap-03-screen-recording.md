## Context

Spec §1 made screen and camera recording non-goals on day one ("a screencast editor's editor without a screencast editor's recorder"). Road map 2 §4 left capture as the user's call. Road map 3 took the screen half, because a screencast is the input the product was shaped around. Camera capture needs a second capture stack, and callouts need a metadata format plus an Input Monitoring grant, so both stayed out. The work added no op, no model field, no FFI export and no schema bump. It added one tool (`record_screen`), a recorder panel, a menu-bar status item and a landing path. R2 then added pause/resume, which ScreenCaptureKit does not provide, and moved the recording's controls into the menu bar at the user's request.

## Decisions

- **A recording is ordinary media, and the model learns nothing.** The file goes through File ▸ Open's own import path (`adoptImported`) or Add Media's two-try placement. There is no source kind, flag or schema change, so every op, cache and export already handles it. (orig §0 dec. 1; spec §11)
- **The file lives in `~/Movies/Reelcut Recordings/`, never in the package or the temp dir.** An untitled document has no package, and a recording is original footage, so it cannot go where caches are regenerable. Consolidate carries it in. `-RCRecordingFolder` overrides the location for proofs. Names follow the Screenshot app's spelling (`Screen Recording <date> at <h.m.s>.mov`), with ` (2)` added on a collision. (orig §0 dec. 2)
- **The canvas takes the recorder's rate (30/60), and the media record keeps the file's honest variable rate.** ScreenCaptureKit only sends a frame when the screen changes, so a probe measured 24981/1000 and 42381/1000. Without the override, that rate would become the timeline grid. `set_canvas` is not used afterwards because the untitled document's first project is not an undo step. (orig §0 dec. 3, R0 q4)
- **The panel asks for grants; `record_screen` never does.** The tool reads Screen Recording and Microphone status synchronously and refuses with the fix in the sentence. The microphone status is read BEFORE any `AVCaptureDeviceInput` exists, because that initializer prompts on its own. The panel asks unconditionally on a press. An early `canAsk` gate made a `notDetermined` microphone unrecoverable under `-AgentServerEnabled`. (orig §0 dec. 4, R1 record)
- **The refusal order is the caller's own mistakes first, then the grant, then the display/window lookup.** This keeps argument errors reachable on an ungranted machine, as `transcribe` does. The ordering rows in the proof kill a grant-first mutant. (orig R1d)
- **The microphone is a second `.m4a` file from `AVCaptureSession` + `AVCaptureAudioFileOutput`, never on the SCStream.** Measured: with `capturesAudio` and `captureMicrophone` both on, `SCRecordingOutput` writes ONE stereo track that is their SUM, which clipped at peak 1.218 in a smoke run. A cutter cannot separate them afterwards. The microphone lands on its own "Microphone" back track at the MEASURED per-segment did-start offset, never at a constant. (orig §0 dec. 5, R0 q2, q6b)
- **The capture session starts first, during the countdown (`prepareMicrophone`).** Starting inside `start` lost 421 ms of voice. With a prepared session the mic leads the picture by 65–75 ms, and the landing head-trims it. Session-first also gave the smaller offset, centred near zero; stream-first gave ~80 ms of picture with no mic. `session.startRunning()` blocks main for 100–180 ms, which is why it runs in the countdown. Since B27 the panel's meter reads that PREPARED session through the 3-2-1 (`publishMicrophoneLevel` while idle with a running prepared session; the tick armed at `beginCountdown`), and the discard publishes silence: the file output's connection was measured reporting levels on a running session before `startRecording` (2026-09-30, #98's comment — the real inputs moved with room noise; the virtual ones read a flat floor either way). (orig R0 q6b, R1 record; #98 c)
- **The picture uses `SCRecordingOutput`, with no `AVAssetWriter`.** `addRecordingOutput` goes BEFORE `startCapture`. Every call has a completion-handler form, so no `async` exception was needed. `recordingOutputDidStartRecording` arrives ~90–100 ms BEFORE `startCapture`'s completion, and the state machine tolerates that. (orig §2, R0 q2)
- **The composition holds a media's last frame when its video track ends early.** A screen recording's video track ends at the last screen change while audio runs on. AVFoundation renders the uncovered range BLACK (measured: picture at 1.5 s, black from 3 s). The fix is `CompositionBuilder.heldTail`, applied before speed scaling. The fix is in the composition, not the recorder, and a fully covered media is byte-identical. The filmstrip's held tail reads the track's last sample time through an `AVSampleCursor`, not the nominal rate. (orig "What R0 changes", R1 record)
- **`size: best` computes pixel dimensions itself.** `captureResolution` `.best` at point size gives a point-sized file. Pixels come only from `width`/`height` asked in pixels, read from `CGDisplayCopyDisplayMode`, because `CGDisplayPixelsWide` reports points on Retina. H.264 rounds odd heights up. (orig R0 q4)
- **Show Clicks forces a BGRA pixel format.** `showMouseClicks` applies only under BGRA, and a fresh config is `420v`. `excludesCurrentProcessAudio` is ALWAYS true, so timeline playback stays out of the file. HEVC is used when offered, else H.264, and the container is `.mov`. (orig R0 q6a, R1a)
- **The programmatic filter always excludes Reelcut** (`excludingApplications`). It removes 99.19 % of an excluded app's pixels. Whether a PICKER-made filter honours `excludedBundleIDs` for capture was never measured. It has been moot since R2 hides the panel for every source. (orig R0 q3)
- **`RecordingLanding` answers ops and predicted ids, and each door commits through its own path.** The panel uses `document.performGroupedEdit`. The tool uses `AgentServer.performGroupedEdit` / `editResult`, so a tool refusal never becomes a sheet. The ops come back unscoped and the door stamps the scope. (orig "What R0 changes")
- **The destination is `.document(recipeKey:)`, not `ObjectIdentifier`.** Object identifiers are reused at the same address after a close. A `recipeKey` is never minted twice, so a closed target falls back to `.newProject` exactly. (orig "What R0 changes")
- **The new-project order is a contract.** `openUntitledDocumentAndDisplay(false)` → `adoptImported` (first segment) → the import change-count → the remainder's one edit → `makeWindowControllers` → `showWindows`. Without the explicit import count, one ⌘Z left a new recording clean and ⌘W closed it without a prompt. (orig R1 record, R2b)
- **One grouped edit for all segments and mics ("one list, one limit").** A refused microphone pair takes the pictures down with it, and the files are named in the refusal. Landing half a recording with no undo step saying so was judged worse. A file the core cannot make any clip of lands as media with a note instead. (orig R1 record; `RecordingLanding.swift` doc)
- **A paused recording is a sequence of files over one stream.** ScreenCaptureKit has no pause. A pause REMOVES the recording output (its file closes in 5–25 ms). A resume ADDS a new one to a new file (starts in 8–10 ms), and the stream captures at ~57 fps throughout. The mic writer stops and restarts per segment on its one session. Each segment is named by its own start time, carries its own offset, and lands as a touching clip. Nothing joins the files afterwards. (orig §0 dec. 6, R0 q7; spec §11)
- **Segments land back to back on ONE track, with each end READ BACK from the trial.** The two-try rule applies to the whole sequence: all segments go on the front track, or all on a new one, so a recording never reads as two. At an inexact canvas rate, an `add_clip` at the previous end snapped DOWN into a one-tick overlap and minted a cross dissolve. So the rule is "touching, or a sub-frame gap, never an overlap". A segment's mic is floored at the previous mic's end, with head-trim rather than late placement. (orig R2b, R2 record)
- **The result has no first-segment conveniences.** `RecordingResult` carries `segments` and has no `micDescriptor` or `micOffset`, so a reader built for one segment fails to compile rather than going silently wrong. `pauses` is a STORED count, because `segments.count − 1` read 0 for a recording paused once and then stopped. (orig R2a, R2 record)
- **The panel orders out when the recording starts, for every source, and returns only with a note.** The status item is the recording's chrome: Pause/Stop, then Resume/Stop while paused, the coral dot, and the pause glyph with a frozen time, at one fixed width measured from its widest title (9:59:59). Pause and Resume have NO key; since B17 File ▸ Pause Recording (Resume Recording while paused) is a second door, with no MCP mirror (spec §11 recording). ⌥⌘N reads Stop Recording while a recording runs. ⌘Q while recording cancels the quit and opens the item's menu rather than finishing silently. There is no global hotkey, because it would need its own grant. (orig §0 dec. 7, R2c, §4)
- **`record_screen` is an off-main app-state tool with no `scope`.** It waits through a semaphore with `onMain` hops. It is bounded at `seconds + 30` for the start and a stop ceiling that grows with the segment count. Its span is WALL CLOCK, so a person's pause shortens what an agent's call records, and the result says so. A named `project` that does not resolve is refused, not silently redirected to a new document. (orig R1d, R2d, R2 record)
- **A microphone problem never fails the recording.** It becomes `micProblem` on a success. A picture that will not probe was the whole recording's failure until B17 (#97): now that segment is LEFT OUT and named in the result's `unreadable` with the files it kept, and only a recording with no readable movie fails, naming every file. Since B27 (#181) a CLOSED segment whose recording output reports a did-FAIL after its stop is left out the same way, unprobed, with the writer's sentence as its reason; only the did-fail of the segment still recording is the recording's failure. A mic failure at a segment boundary (a did-finish the machine asked for) is that segment's `micProblem` only, never the session's `microphoneProblem`. (orig R1 record, R2a; spec §11 recording)
- **The microphone needs the hardened-runtime entitlement `com.apple.security.device.audio-input` plus the plist usage key.** A bare `swiftc` probe needs neither, so spike rows measure the framework, not the app. (orig R0 closing)

## Known limits

- **TCC attribution:** a shell-launched binary runs under the TERMINAL's grants (R0 q1). A proof's instance therefore never tests Reelcut.app's own grant. `open -a … --env … --args …` gives an instance responsible for itself. `open -a` activates an existing instance instead of launching a new one.
- **Host state is a proof input.** A locked console lists 0 shareable displays under a true preflight. A muted output reaches the tap unreliably. Another app's sound lands in the tap. A Bluetooth OUTPUT gives the system-audio tap digital silence. A Bluetooth INPUT makes the mic lag the picture (see #57). The proofs skip these by name.
- **A variable-rate recording in a new project gives an inexact canvas rate only via File ▸ Open**, not via the recorder. At such a rate, "touching" segments may have a sub-frame gap.
- **Stopping and pausing edge cases** (documented in `ScreenRecorder+Pause.swift`):
  - A pause within ~10 ms of a resume's add can close an unopened file. Since B17 that empty movie is left out and named, not the recording's failure.
  - A mic start then stop before its first sample gives −11805 with no file. Since B17 it is that segment's `micProblem` alone, not `microphoneProblem` for the whole session.
  - A mic writer poisoned by a device profile switch (AirPods on first use, `'pck?'` −11800) fails every later segment's mic file.
- **A label past 9:59:59 is wider than the status item's one length.** The item is sized for ten hours; a longer recording's title is wider than `itemLength` (unmeasured how the bar draws it).
- **The countdown's meter holds its last pre-roll level through the ~0.1–0.2 s of arming**: the recorder publishes nothing while `.arming`, and `ScreenRecorder.swift` (399) was not touched to meter there (B27).
- **`recordedDuration` on `SCRecordingOutput` is whole seconds.** It serves the timer only, never an offset.
- **Structural-only coverage:** four rules are read, not driven, by the probe — the tool's `try?` on a nil, `freeze()`, the quit guard's `openMenu()`, and the panel close in `.starting`.
- **Rejected or left out:** camera recording (a second capture stack; spec §1 non-goal); keystroke/click callouts (event tap plus Input Monitoring; only `showMouseClicks` is taken); a global stop hotkey (needs a grant); trimming the countdown or any post-processing; recording into the package; HDR (the pipeline is 8-bit BGRA); a `.microphone` stream output for the meter (it works, ~94 buffers/s in the device's native format, but it is moot). The meter polls `AVCaptureAudioChannel` levels at ~28 Hz from main instead, with no queue.
